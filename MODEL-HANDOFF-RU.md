# UV98 Rust — передача проекта другой модели

Состояние на 9 ноября 2026, Asia/Omsk. Это самостоятельная точка входа без истории
чата. Пользователь просит продолжить разработку удобной радиолюбительской прошивки
на Rust и собственной CPS для iRadio UV‑98 Plus. Основа исследования — stock1.16,
схема родственной RT880, сохранённые данные конкретной станции и результаты опытов.

**Первый следующий этап: довести спектр и обычное управление до цельного рабочего
результата, сохранив ускорение r5 и корректный возврат RX/A/B.** Не начинать заново
разработку платы/загрузчика и не подменять работу новым общим планом. Сначала прочитать
перечисленные документы, сверить код, затем реализовывать один согласованный этап.
В момент передачи задача — документация; работа с рацией остановлена владельцем.
Новый COM-сеанс/запись/радиопередача не запускаются автоматически из этого файла.

## Решения владельца, которые нельзя потерять

- Большие завершённые этапы, минимум повторных вопросов; пользоваться уже данным
  контекстом. Уточнять только фактически отсутствующее и нужное для текущего действия.
- Портрет240×320, сверху A/снизу B одновременно; независимые MR/VFO и зоны.
- Красная EXIT отменяет временную функцию/редактор и ведёт назад, при необходимости
  несколькими нажатиями. Не заставлять искать повторное долгое нажатие для отмены.
- Верхняя и нижняя PTT должны назначаться на A/B/активный или другую функцию;
  длинные0..9 назначаемые. Реальный нижний сигнал сначала определить.
- Иконки реальных функций, раздельные таймеры/вкл/выкл подсветки LCD и клавиатуры;
  пользовательские цвета позже. Справочник владельца: `docs/images/radio-icons-reference.png`.
- Обычный сканер и удобный спектр, RF-маршруты CB/VHF/UHF/800, отдельный КВ;
  GPS/APRS и исследование DSP. Все ограничения реализации указаны в41ID.
- Stock не возвращать после каждого опыта: прежнее восстановление уже работало.
  Личные данные и stock сохранять. Не навязывать разборку/SWD, когда есть решение кабелем.
- EXO-only, LOW-only, один тон и5s — отменённые отладочные ограничения. В r5 общий
  калиброванный FM-профиль; ordinary TOT30s, release/fault/валидность плана остаются.
  Безусловное TX на любой частоте не реализовано. AM TX не выдавать за готовый backend.
- Нет автоматических передач/APRS-маяков. Ранее данное разрешение на опыт не означает,
  что сейчас станция подключена, в том же COM/режиме или ожидает запись.

## Первое задание новой модели: один законченный этап

**Цель:** найти активность на понятном спектре, выбрать сигнал, послушать и вернуться
в тот же обзор либо исходный A/B без потери контекста и лишней перенастройки.

1. **Restore и владение RF.** В `firmware-diagnostic/src/main.rs` обработчик
   `scope::Completion::Restored` ставит `current=None`; далее `receive_changed`
   повторно запускает stop/receive. Вернуть точный подтверждённый `RxRequest` из
   Scope и сравнивать полный контекст с актуальным wanted. Не просто присвоить
   wanted как будто он уже применён. Тестировать связку main-policy/Scope/App,
   отмену во время restore, A/B, разные width/tone/options и ровно один нужный RX.
2. **Модель спектра.** Отдельный RAM `SpectrumConfig`: центр/границы/шаг/размах,
   checked arithmetic и ограничения всех точек по calband/route/offset. Не менять
   обычный VFO step скрыто. Отдельные Sweep/Pause/Listen/Restore/Fault и конкретные
   причины отказа; bounded deadlines, поздние ACK и отмена не возобновляют TX.
3. **Понятный UI.** Частоты начала/центра/конца, курсор, RAW min/max, прогресс/возраст,
   различие ещё не измеренной и старой точки, peak-hold/clear и найденного максимума.
   MENU открывает варианты/подтверждает, EXIT отменяет. Прослушивание не теряет окно;
   перенос частоты в A/B — явное действие. Не обещать одновременный приём со sweep.
4. **Скорость.** Уменьшить redraw и лишнюю работу, сохранить обработку клавиш/PTT.
   Сейчас обновление графика помечает149 строк; bus+settle дают теоретическую нижнюю
   оценку около1.48s/81точка без CPU/UI, а не измеренную скорость. Не ускорять картинку
   вымышленными данными и не удалять RF guard/settle только по чужому примеру.
5. **Мелкие, но видимые несогласованности.** About всё ещё r4; нижнее назначение
   скрывает unmapped; Step меняется сразу, другие Settings подтверждаются MENU;
   saved/effective power не различены, отказы слишком общие. Закрыть вместе с управлением.
6. **Выход этапа.** Целевые host-тесты/симуляции, затем полный новый image build,
   проверка ELF/stack/упаковки; SHA и новый отдельный каталог. Подготовить короткую
   программу живой проверки. До возобновления аппаратной работы владельцем не прошивать.

Минимальная приёмка: полный круг Home→Spectrum→Listen→Spectrum→EXIT из обоих A/B,
исходные частота/MR/VFO/зона/width/tone/options восстановлены; нет второго ненужного
RX; ошибки/таймауты завершаются явно; нет самопередачи; измеренные данные привязаны
к правильным частотам; неизвестное не рисуется нулевым измерением. На железе позднее
измерить sweep/input/render/RX-restore отдельно. Sim PNG и ACK этого не доказывают.

DMA/водопад — следующая оптимизация того же интерфейса, если базовый сценарий уже
готов. Две строки RGB565240px занимают960B; framebuffer240×320 —153600B и не подходит
нашему64KiB SRAM-профилю. Аппаратный scroll/геометрия/сброс и ошибки DMA требуют
отдельного доказательства. При необходимости разбить этап на внутренние коммиты,
но передавать владельцу связный результат, не набор декоративных пунктов.

## Следующие приоритеты после первого этапа

Слабый AM/ATIS и обычный RX; голос/TX-stop/TOT r5; все кнопки/подсветки/A/B/зоны/scan.

## Референсы и пределы переноса

- RT880: `619fa079c657433798cd4475997ecaf476e5cd73`. Полезны zoom/selection/waterfall,
  dirty-region/DMA и Si47xx architecture. Есть savedVfo/memset и другие ошибки,
  LCD SPI1/AF5 отличается от нашего работающего SPI3/AF6. Общая лицензия авторского
  кода не найдена; сторонние C/patch/картинки в этом исследовании не копировались.
- CW: `ff2547182e8557de61298c53ef76dfc9870374c4`. Полезны threshold/listen/skip,
  AM RF gain и CW FSM; Spectrum выключен по умолчанию, обнаружены границы массива
  и бесконечное ожидание. Apache-2.0 не отменяет атрибуцию конкретных файлов.
- AM gain-control не равен DSP шумоподавлению и не доказывает исправление ATIS.
  Наличие CMSIS-DSP в дереве не равно работающему приёмному PCM-потоку.
- Karina остаётся пользовательским ориентиром функций; [сводка источников](research/reference-cw/README-RU.md)
  и прежние `research/ui/*INSPIRATION*` объясняют, что действительно изучено.

## Команды после изменений, когда входы доступны

Команды ниже — инструкция для будущей работы, при подготовке handoff они не запускались.
Последняя проверенная сборка использовала Rust1.99.1, host`x86_64-pc-windows-gnullvm`,
target`thumbv7em-none-eabi`. Python>=3.11, capstone/unicorn/pyelftools; pyserial для
журнала. PowerShell7. Зависимости закреплены Cargo.lock, build использует `--offline`.
Если кэша нет, предварительно получить зависимости обычным `cargo fetch --locked`.

В Windows, из рабочего проекта с fixture:

```powershell
$env:PATH = (Join-Path $env:USERPROFILE '.cargo/bin') + ';' + $env:PATH
$taskRustInfo = & rustc -vV
$taskHost = ($taskRustInfo | Where-Object { $_ -match '^host: ' }).Substring(6)
if ($taskHost -eq 'x86_64-pc-windows-gnullvm') {
    $taskSysroot = & rustc --print sysroot
    $env:CARGO_TARGET_X86_64_PC_WINDOWS_GNULLVM_LINKER = Join-Path $taskSysroot 'lib/rustlib/x86_64-pc-windows-gnullvm/bin/rust-lld.exe'
}
rtk cargo test --locked --offline --target $taskHost -p uv98-spectrum -p uv98-rf-sequence -p uv98-radio-runtime -p uv98-handheld-ui -p uv98-handheld-app
```

Если RTK отсутствует, вызвать `cargo test` с теми же аргументами. Этот набор не
заменяет полный build. Нужные новые tests выбираются по поведению/регрессии,
а не только по совпадению с реализацией. Исправления formatter делать в своих файлах.

## Аппаратный сеанс — только когда он действительно возобновлён

COM20/CH340 — прошлый порт, не доказательство текущего подключения. Ошибка Windows31
возникала при настройке DCB/SetCommState; replug помогал, причина не установлена.
Это не WindowsAccessDenied5. Не требовать бесконечных одинаковых переподключений.
Штатный загрузчик раньше включался PTT+power: чёрный экран/зелёныйLED; обычный старт
без кнопок. Последний режим устройства сейчас не проверен.

На исходном ПК инструменты — `work/live-hardware/flash_fixed_image.py`, соответствующий
`verify_diag018r5_oracle.js` и `capture_boot_log.py`. В Git их архивные копии находятся
в `tools/session-archive/` и `tools/boot-log/`. Flasher закрепляет образ/протокол/SHA/
workspace: не универсальная команда для нового BIN. Сначала отдельно подготовить
и проверить новый профиль/байтовый oracle и восстановление. Не обходить его проверки.
Для записи/журнала один владелец COM; готовность прошивки не доказана одним ACK.
