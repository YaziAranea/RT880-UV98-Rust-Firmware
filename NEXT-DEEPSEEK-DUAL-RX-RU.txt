КОНКРЕТНАЯ ЦЕЛЬ
На верхней карточке A принимается одна частота, на нижней B — другая.
Обе физические цепи приёма работают одновременно. A и B независимо могут быть
MR или VFO, иметь свои зоны/каналы/шаг/режим/SQL/CTCSS/DCS/reverse.
Смена фокуса UI выбирает редактируемую карточку, не перенастраивает второй RX.
Не подменять цель быстрым A/B-переключением одного RF-чипа, TDR/dual watch,
двумя нарисованными RSSI или созданием двух программных Runtime.
Отдельно доказать: (1) два одновременных RF RX; (2) выбор звука; (3) слышимость
обоих сигналов одновременно. Если смешивание физически невозможно, прямо указать
ограничение. Автоматический приоритет одного звука не закрывает пункт (3).

receiver -> chip -> RF input/antenna -> filters/relay -> calibration ->
init/wake -> freq/mod/width -> RSSI/SQL/tone/AGC -> AF output -> speaker.
Отдельно общие ресурсы: PF0, A33/B33, PC4, PF8, питание, TX/PA, усилитель.
Для пар VHF+UHF, VHF+VHF, UHF+UHF, air-AM+FM, CB+FM, 800+FM указать

ЧТО УЖЕ ИЗВЕСТНО (ПЕРЕПРОВЕРИТЬ ПО ИСТОЧНИКАМ)
RF A/U201: CS PA8, DATA PC9, SCK PF6; stock write0801E660/read0801E620.
RF B/U400: CS PC7, DATA PC6, SCK PC8; stock write0801E6D4/read0801E698.
Это отдельные 3-wire шины, не SPI NOR. GPIO configuration RMW сериализовать.
Frequency A:08004B88, B:08003CCC -> selector08012A30(mode0/mode1).
Cold init A:08004DC0, B:08003D34; RX-start A:08004FA0, B:08003E3C.
B sleep08003EC0; audio-mode A080038AC/B08003A08 — фрагменты, не полная приёмка.
Stock width helper08004228 пишет A43 даже из secondary caller: нельзя механически
превратить это в B43. Secondary selector не обновляет primary noise/SQL cache.
Найденные stock фрагменты принадлежат related RT880 1.16 application SHA256
eaef215cc7084dcd94281bbffb7ab6e2dd1e79ce135f01c90e3dbc691dd16bfc;
это не точный MCU-readback пользовательской UV98.
PF0/K200 общий антенный маршрут. B33 bit4 A/B-SW связан с TX-питанием U403,
не считать его переключателем звука A/B. PC4/U501 SW1 выбирает AFOUT4819 либо
MOD4819B; это тоже не доказанный выбор AFOUT4819B. PF8 — общий mute.

DRX-04. Звук, PTT, Spectrum.
Различать signal_present/tone_match/audio_eligible/audio_routed/stale/paused.
Приглушение одного аудио не должно останавливать RF другого.
Режим «оба слышны» — только при подтверждённом mixer/выходах; не соединять два
AF output программно догадкой и не обещать стерео через существующий разъём.
Dual RX не включает full duplex/crossband repeater/APRS; это отдельные задачи.
Сохранить channel-tx/TOT/release guards. TX использует подтверждённый TX backend,
при TX планирует паузу/защиту RX по реальным общим цепям; после release восстанавливает
оба полных плана. Переименование PTT B не разрешает передавать через второй BK.
Spectrum/scan/Listen получает явное владение RX; второй работает только при
совместимости. Вынужденная пауза показана; EXIT/fault восстанавливает оба контекста.
Не сломать завершённую r6c FSM неявными cancel_temporary/restart-флагами.

ОБЯЗАТЕЛЬНЫЕ HOST-ТЕСТЫ
- Два отдельных адресуемых register banks + один shared-control mock; в каждой
  записи журнала receiver ID. Тест «две переменные» без различимых IO не принимать.
- Одновременно два Receiving на разных частотах, независимые RSSI/SQL/tone/AGC.
- Смена UI-фокуса не пишет tuning registers; retune A не retune/stop B.
- MR/MR, MR/VFO, VFO/MR, VFO/VFO; зоны/tones/reverse не протекают между A/B.
- Неподдержанная/неизвестная пара отклоняется до изменения работающего RX.
- Таймаут/ошибка B не публикуют старые данные как свежие; cleanup идемпотентен.
- Общий mute не выключает допустимый звук другого RX; audio arbitration проверен.
- PTT/release/TOT/fault при конфигурации обоих, восстановление обоих полных планов.
- Spectrum/Listen/отложенный restart/EXIT на каждом разрешённом RX; нет нового TX
  от отменяющего PTT, требуется отпускание и новый допустимый край.
- Wrap таймера, bounded tick, отсутствие starvation и повторного retune без изменений.
- Все исправленные r6c regressions остаются зелёными.
Root твоего этапа один запускает Cargo; субагенты не запускают конкурирующие сборки.
Нужны fmt/host/ARM/layout/фактический fixed stack. Максимальный runtime stack
не считать доказанным по статическому layout; полный framebuffer не вводить.
