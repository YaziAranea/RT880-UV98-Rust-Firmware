Что есть

1. crates/calibration — библиотека no_std без unsafe и зависимостей.
   Читает сохранённые 4096 байт калибровки через неизменяемые ссылки.
   Разбирает общие поля и 15 групп по 112 байт, включая wide/narrow,
   таблицы мощности, шума и шумоподавителя. Неизвестные биты и хвост
   доступны без изменений. Значения — сохранённые коды, не физические
   ватты, герцы или результат измерения.

   Проверяется длина и маркер 0x9A. Это не проверка целостности или
   корректности всех коэффициентов: контрольная сумма формата неизвестна.
   Исходный бэкап и его SHA256 нужны отдельно.

2. firmware — минимальный Cortex-M4 ELF для профиля AT32F423.
   FLASH приложения начинается с 0x08002800; первые 10 KiB не входят
   в область компоновки. Верх FLASH 0x08040000, RAM 48 KiB.
   Включены установка MSP и VTOR, обычная инициализация data/bss.
   После startup программа отключает IRQ и остаётся в WFI.
   Новые библиотеки дисплея, клавиш и SPI вынесены в отдельные crates.
   Stage0 их не вызывает; исполняемая композиция теперь в firmware-diagnostic.
   Радио и UART в старом firmware не реализованы.

   Профиль основан на родственных RT-880 исходниках и документации MCU.
   Маркировка MCU и ревизия конкретной платы физически не сверены.
   Границы ELF сами по себе не предотвращают mass erase программатором.
   Бездействие программы не доказывает безопасное состояние GPIO,
   унаследованное от загрузчика. Это обязательная будущая проверка.

3. tools/check_elf.py — независимая проверка адресов и векторов ELF.
   Проверка структуры не подтверждает работоспособность на железе.

4. build.ps1 — тесты, сборка, проверка ELF, текстовый разбор калибровки.
   Все отчёты пишутся в validation. Программа inspect читает только файл.

5. crates/stock-model — чистые расчёты по выбранным функциям родственной
   RT-880 1.16: выбор записей/точек, поправка частоты, мощность, девиация,
   фильтры, шумоподавитель, ADC/VOX и другие вспомогательные функции.
   15741 результатов ARM-эмулятора сохранены для сравнения с Rust.
   Подробности и ограничения: CALIBRATION-PORT-RU.txt, research/.

6. crates/codeplug — чтение секций .880dmf/.98pdmf, строго 221184 байта,
   разбор известных полей каналов, зон, FM и 24 полей CFG. Точечные
   правки сохраняют остальные байты; неизвестные значения не нормализуются.
   crates/cps-core хранит исходник и рабочую копию, применяет операции
   целиком либо отменяет при ошибке, предоставляет diff и undo.

7. apps/cps — собственная CPS 0.3 для Windows: локальные файлы и COM-чтение.
   Интерфейс редактирует существующие активные каналы, зоны и 24
   настроек CFG; показывает побайтовые изменения, отменяет операции,
   сохраняет новую копию без перезаписи существующего файла.
   Вкладка «Радиостанция» выбирает порт и папку для новых снимков; чтение
   выполняется отдельным worker. При закрытии во время чтения запрашивается
   отмена, приложение ждёт завершения. Папка снимков по умолчанию не выбрана.
   Создания каналов, FM UI, CSV, записи в радио и прошивки в этой версии нет.
   Точные функции, формат и дальнейшие этапы: CPS-PLAN-RU.txt.
   Описание реализации не заменяет отдельный отчёт проверки GUI/сборки.

8. crates/radio-read — ограниченный штатный READ: calibration0..3,
   CFG8..11, Channels16..63, Zones112..239, FM856..859; всего188блоков.
   Два прохода с отдельным открытием/закрытием, проверкой длины, header,
   адреса, sum8 и точным сравнением. Контроль таймаутов, отмена и журнал
   захваченных TX/RX/frames отделены от редактора.
   apps/cps/src/radio.rs сохраняет результат и manifest в новый каталог.
   При штатной ошибке сохраняются доступные captures; аварийное завершение
   процесса до сохранения не гарантирует сохранность промежуточных данных.
   Только проверенный снимок применяется к чистому открытому документу.
   Меняются4секции CFG/Channels/FM/Zones; Time остаётся из базового файла,
   калибровки сохраняются отдельно. Нули вместо непрочитанного Time не создаются.
   Это192512байт выбранных областей, не полный4MiB и не бэкап MCU/загрузчика.

9. crates/board-at32 — опциональный PAC backend SPI2/PB12..15 для READ03.
   Режим3, таймауты, освобождениеCS, запрет остальных NOR-команд. Конструктор
   unsafe с явными требованиями к плате, clock, RF, ownership и timing.
   Default feature выключен; clock и прочие GPIO самостоятельно не меняет.

10. crates/display — потоковый LCD320x240, stock control prefix и raw565.
    Полные окна CASET/PASET, одна очистка вместо двух стоковых; расхождение
    документировано. Physical bus ещё не реализован/проверен, SPI2EN требует
    отдельного исследования. crates/keys — stockdecoder матрицы/ADC/PTT,
    отдельный debounce с явно заданными временами, без GPIO-драйвера.

11. crates/diagnostic — связка4096байт калибровки + один48байт канал изNOR.
    Только чтение, UP/DOWN меняют номерслота, PTT ничего не делает.
    Рендер использует640байт на строку вместо153600байт framebuffer.
    apps/diag-sim — Windows CLI: читает4MiB файл, моделирует NOR иLCDbus,
    сохраняет2PNG иJSON. Это проверка протокола наПК, не запуск на рации.
    Подробности этапа: DIAGNOSTIC-STAGE-RU.txt.

Сборка в Windows

Нужны Rust, целевая библиотека thumbv7em-none-eabi и Python 3.
На этой машине target уже установлен. Зависимости закреплены Cargo.lock.

  powershell -NoProfile -File .\build.ps1

На Windows gnullvm скрипт использует штатный rust-lld из Rust sysroot.
Настройки действуют только внутри процесса; глобальная конфигурация
Rust и PATH не меняется. Для остальных host targets нужен их обычный linker.
Скрипт не устанавливает системные пакеты и не содержит команды прошивки.
Cargo может скачать зависимости из crates.io при первой сборке.

Отдельная сборка приложения CPS для Windows:

  powershell -NoProfile -File .\build-cps.ps1

Скрипт запускает проверки библиотек CPS и release-сборку приложения.
Переносные файлы: target\cps-portable; отчёты: validation\cps-*.json.
Тесты не заменяют отдельную проверку GUI. COM-порт скрипт не открывает.

Схема полей: статический разбор ReadDataToUI и FillBand программы

Программа не запускалась для создания этого проекта.

Сохранённый ранее 4 MiB дамп покрывает адресное пространство штатной
команды чтения, соответствующее основной области внешней SPI NOR.
Внутренняя Flash MCU и штатный загрузчик этим дампом не сохранены.
Подробности профиля и ссылки: HARDWARE-EVIDENCE.txt.

Для работы CPS пользователь назвал 999.880dmf самым свежим сохранённым
файлом на 2026-11-08. Актуальность указана пользователем, а не выведена
из файла. Это не полный дамп: в legacy CPS-файле нет калибровочной области,
прошивки MCU и загрузчика; обычное штатное чтение не обновляет bufTime.
Собственная CPS сохраняет исходные байты этих файлов, не приписывая
непрочитанной Time доказанную свежесть. COM-чтение получает отдельный новый
калибровочный снимок; ранее сохранённые калибровки/бэкапы не заменяются.

Следующие этапы

1. Получить точный чистый recovery image UV-98 Plus 1.16 и проверить
   штатный загрузчик, диапазоны стирания и возврат при сломанном приложении.
   RT-880-labelled BIN не считать доказанно идентичным пользовательскому.
   Заблокированный Defender EXE не восстанавливать и защиту не обходить.
   Полный бэкап MCU без изменения прошивки пока не получен.
   Снятие защиты чтения может стереть память; это не способ сделать бэкап.

2. Расчёты выбранных стоковых путей уже перенесены. Проверить оставшиеся
   режимы/override и точный UV98-код; связать модель с будущими драйверами.
   Сохранение байтов и совпадение расчётов ещё не подтверждают физические
   мощность, девиацию или точность частоты.

3. Подготовить раннюю инициализацию с проверенным состоянием RF,
   затем питание, часы, дисплей, клавиши и приём. Передача — отдельный этап
   после аппаратной проверки и измерений. На этой стадии TX не реализуется.

4. Собственная CPS 0.3: проверить актуальные сборку, GUI и транспорт чтения;
   конкретные выполненные проверки фиксировать в validation с хешем EXE.
   Затем отдельно расширять codec и UI: создание каналов, FM, CSV и VFO.
   Запись в рацию остаётся отдельным этапом; текущие чтение и экспорт
   файлов не подтверждают готовность к аппаратной записи.
