ДОСТУПНОЕ МЕНЮ: ВСЕ 20 УНИКАЛЬНЫХ ПУНКТОВ
Корень: прямой «РЕЖИМ FM / AM» плюс пять групп. Тот же FM/AM повторяется
в группе «ПРИЁМ И TX»; это одна функция, не два независимых режима.

«КАНАЛЫ / VFO»:
1. КАНАЛ / ЧАСТОТА — ПОДКЛЮЧЕНО. MR/VFO каждого A/B, новый RX через policy.
   Приёмка: независимость соседнего слота, корректное retune/ошибка диапазона.
2. ВЫБОР A / B — ПОДКЛЮЧЕНО. Один активный RF-приёмник, второй слот — контекст.
   A/B на экране наблюдались; независимые настройки полностью live не приняты.
3. СПИСОК КАНАЛОВ — ПОДКЛЮЧЕНО. Реальные активные записи NOR, фильтр/порядок зоны,
   MENU выбирает, затем retune. Синтетические/неактивные каналы не создаются.
4. ЗОНЫ КАНАЛОВ — ПОДКЛЮЧЕНО. Сохранённые зоны или «Все», отдельно A/B; только
   чтение. Приёмка: пустая зона, неверный member, исходный порядок и смена A/B.
5. ДАННЫЕ КАНАЛА — UI/read-only. RX/TX, тоны, ширина и сохранённая мощность.
   ПРОБЕЛ: мощность из raw record может отличаться от действующего RAM override;
   надпись не поясняет «сохранённая». Параметры канала здесь не редактируются.

«ПРИЁМ И TX»:
6. РЕЖИМ FM / AM — ПОДКЛЮЧЕНО. RAM override активного слота, FM/AM RX/audio.
   AM TX отсутствует. AM относительно стока плохой, R-02 открыт; host≠качество.
7. МОНИТОР — ПОДКЛЮЧЕНО. Явно обходит SQL/RX-tone gate, EXIT отменяет. Шум
   физически слышали; полная live-проверка отмены и возврата tone gate не принята.
8. МОЩНОСТЬ L/M/H — ПОДКЛЮЧЕНО. Значения 0/1/2 → заводской PA-код для TX.
   Это не ватты. По умолчанию RAM override=LOW, а не восстановление сохранённой
   мощности каждого канала; это действующее поведение, требующее ясной подписи.
9. РЕВЕРС RX / TX — ПОДКЛЮЧЕНО только MR. Меняет обе пары частота/тон в RAM,
   не запись NOR. Host есть, duplex/reverse на живом тракте не принят.
10. ШАГ ЧАСТОТЫ — ПОДКЛЮЧЕНО: 2.5/5/6.25/10/12.5/25 kHz. Влияет на VFO,
    скан и ширину спектра. ПРОБЕЛ: стрелки меняют шаг сразу; EXIT не возвращает
    прежний шаг, в отличие от draft-поведения девяти Setting-редакторов.

«ПОИСК / СПЕКТР»:
11. СКАНИРОВАНИЕ — ПОДКЛЮЧЕНО. MR: каналы выбранной зоны; VFO: окно ±500 kHz
    в допустимом диапазоне/текущий шаг. Dwell 150 ms после Receiving, удержание
    по audio_open, продолжение через 500 ms тишины. PTT/ручное действие/EXIT
    останавливают без автоматического TX. Host есть; полный live-сценарий открыт.
12. СПЕКТР ЧАСТОТ — ПОДКЛЮЧЕНО к реальному RSSI, но UX/realtime НЕ ПРИНЯТЫ.
    81 точка, текущий RX — центр, ширина 80×шаг VFO; подробности ниже.

«КНОПКИ»:
13. ДОЛГИЕ КЛАВИШИ — ПОДКЛЮЧЕНО. Назначаются все десять цифр, MENU commit,
    EXIT cancel, RAM. RF-действие лишь запрос, исполняемый main. Live-полнота открыта.
14. БОКОВЫЕ КНОПКИ — ЧАСТИЧНО ПОДКЛЮЧЕНО. Верхняя PB6 реально поступает в main;
    нижняя редактируется в UI, но LOWER_PTT_CODE=None, физический вход не связан.
    ПРОБЕЛ: экран «НИЖНЯЯ КНОПКА» не сообщает об отсутствии этого подключения.
15. ПРОВЕРКА КНОПОК — UI/diagnostic. Показывает нормализованные клавиши/матрицу/PTT.
    Не подменяет ADC-телеметрию и не доказывает назначение нижней кнопки.

«СВЕТ / СИСТЕМА»:
16. СВЕТ ЭКРАНА — ПОДКЛЮЧЕНО через lighting→PA4.
17. СВЕТ КНОПОК — ПОДКЛЮЧЕНО через lighting→PA9.
    Обе политики независимые: OFF/ON/5/10/20/30/60 s, глобальные RAM.
    Произвольного числа секунд/PWM-яркости нет. Полная физическая независимость
    и таймеры не приняты; работающий экран сама по себе этого не доказывает.
18. КАЛИБРОВКИ — UI/read-only. Результат стартового SHA-сравнения 4096 B;
    это не редактор и не повторное чтение по MENU. R5 boot подтвердил match.
    Тонкая правка/backup доступны отдельно в CPS и не пишутся в рацию.
19. УПРАВЛЕНИЕ — UI, статическая справка. Описывает основные клавиши и RAM-подход.
    Требует сверки после изменения управления спектром/назначений.
20. О ПРОШИВКЕ — UI. КОНКРЕТНЫЙ ДЕФЕКТ: S2::about показывает «0.1.8-r4»
    при установленном r5. Версия должна идти из единой release metadata.

НАСТРОЙКИ И ПРЯМЫЕ КЛАВИШИ
Все 9 Setting: Mode, Power, Monitor, Modulation, Reverse, ActiveSlot, Scan,
DisplayLight, KeyLight. Стрелки выбирают draft, MENU применяет, EXIT отменяет.
RF-настройки подтверждает report runtime, свет — подтверждённая RAM-политика.
Настройки SQL, ширины VFO, CT/DCS, TX-offset, mic gain, произвольного TOT,
GPS/APRS/DSP отсутствуют в текущем меню. SQL/mic/volume читаются из сохранённой
CFG; ширина/тоны каналов берутся из записи. Это не полный аналог stock UI.

Home: ↑↓ канал/VFO, цифры номер или 6/7/8-значная частота, MENU commit/меню;
EXIT отменяет ввод целиком и временные функции. Долгое EXIT — Home.
Короткое * — MR/VFO, долгое * — A/B; короткое # — шаг, долгое # — блокировка.
Долгое MENU также переключает MR/VFO. Во время ввода длинные цифры не запускают RF.
В Keys часть обычных действий подавляется для диагностики; MENU/EXIT выводят назад.
Ввод допускает UI-диапазон шире RF-backend: недоступная частота может попасть
на Home с RadioUnavailable. Нужна ясная причина отказа, не обещание HF-приёма.

Все 14 назначений долгих цифр: None, Power, Monitor, Scan, Reverse, Mode,
Step, Channels, Keys, Lock, Modulation, Zones, SwitchSlot, Spectrum.
Defaults 1..9: Power/Monitor/Scan/Reverse/Mode/Step/Channels/Keys/Lock;
0: Spectrum. Настраиваемы, только RAM. Все ветви есть в S1::shortcut и S4.
Все 7 боковых назначений: PttA, PttB, Active, Monitor, Scan, Power, None.
Верхняя может выбрать B без второй физической PTT. Нижняя — НЕ ПОДКЛЮЧЕНО.
Прямого назначения Spectrum на боковую кнопку нет.

Все 13 Request имеют обработчик S4: CyclePower, ToggleMonitor, StartScan,
StopScan, CycleModulation, SetPower, SetMonitor, SetModulation, SetDisplayLight,
SetKeyLight, StartSpectrum, StopSpectrum, AcceptSpectrum. Наличие обработчика
не означает успех: invalid plan/state может вернуть отказ. Общий TxDisabled /
RadioUnavailable сейчас не объясняет AM-TX, RX-only, диапазон, границу спектра
или временный конфликт; это важный UX-пробел.

СПЕКТР: ЧТО ЕСТЬ И ЧТО НУЖНО ДОВЕСТИ
Это последовательный обзор RSSI одним трактом, не FFT и не одновременный wideband.
Сейчас 81 bin, центр активного RX, шаг VFO 2.5..25 kHz, полоса 0.2..2 MHz.
Курсор ↑↓; MENU выбирает измеренную частоту и выходит в Home/VFO после restore ACK;
EXIT/PTT отменяют и возвращают исходный RX. PTT здесь не начинает передачу.
Valid/fresh/peak masks, bounded tune/read, защитные проверки PA/gates и билеты
ACK есть. Граница calband/route отклоняет всё окно, не обрезает его автоматически.

Наблюдения renderer (код + synthetic PNG, не RF-приёмка):
- Большая частота не подписана как курсор; центр/span/шаг не объяснены.
- Сетка без чисел, RAW 0..511 без полезной относительной шкалы.
- Свежесть различается цветом; номер/ход sweep не показан; peak всегда включён,
  ClearPeaks отсутствует в UI. Нет pan, center/span editor, pause/listen/restart.
- Нет данных иногда соседствует с общим «RX: ПРИЁМ СИГНАЛА»; Restoring ещё
  предлагает «MENU ЧАСТОТА». Подсказки должны соответствовать реальному state.
- Повторные пояснения mute/PTT и мелкий текст перегружают экран.

Наблюдения runtime-аудитора S8:
- Минимум одного bin: 6 записей + 11 чтений с readback/PA guards, затем settle.
  Оценка по задержкам кода: ≥8.27 ms обмен +10 ms ожидание; 81 bin ≥1.48 s
  ДО GPIO/CPU/UI/prepare. Это нижняя расчётная граница, не измеренная скорость.
- Snapshot допускается раз в 250 ms и только после предыдущей отрисовки;
  изменённый plot затрагивает 149 строк /19 пачек по 8. Wire-only минимум
  47.68 ms при 12 MHz не включает подготовку/CPU. Частота snapshot не sweep rate.
- Конкретный лишний путь: полный RX restore в Scope, затем main current=None
  заставляет receive_changed(None,wanted) повторно stop/full RX. Даёт лишнюю
  задержку/mute; исправление ещё не выполнено.

Предложения агентов, НЕ новые утверждённые функции пользователя: компактный
общий с Home дизайн; подписи центр/полоса/курсор, относительная шкала без dBm,
progress/возраст данных; затем осмысленные span/pan/hold/listen/clear peaks.
До выбора управления согласовать взаимосвязь экрана, режима обзора и приёмника.
Приёмка: известный источник даёт пик в нужном bin; новые/старые/неизмеренные
данные различимы; измерены sweep и input latency; EXIT/PTT не оставляют mute
или TX; один restore возвращает исходные частоту, режим, SQL и тон; MENU
применяет только valid bin. Пользователь подтверждает цельность и читаемость.

RF / СОХРАННОСТЬ / ЧТО НЕ НУЖНО ПРИПИСЫВАТЬ УСТРОЙСТВУ
- Общий FM TX: S5::tx_policy, актуальный профиль, выбранный калиброванный план,
  одна чистая физическая PTT, release-to-arm, фиксированная сессия, TOT 30 s,
  fault/HardFault/watchdog shutdown. EXO/LOW/5 s allowlist в r5 снят.
- R5 capture: READY и onboard SHA-match, RX state, ввод. Последний 170 —
  Configuring; из отсутствия дальнейших кадров нельзя вывести TX/stop/зависание.
  Собственная речь через репитер подтверждена только в предыдущем r4-тесте.
- Отображаемые route/RX/TX — состояния исполняемого кода; это не контактный
  датчик реле и не измерение ватт. PF0 и электронные gates реализованы, полная
  карта CB/V/U/800 физически не принята. BK B остаётся asleep, A/B не dual RX.
- AM-приём реализован, качество остаётся известным дефектом. AM/SSB TX нет.
- GPS: parser+stock evidence; UART не интегрирован. Модуль есть по пользователю.
- Si4732: evidence bus/power, но chip/reset/audio не квалифицированы. Ниже18 MHz
  нет рабочего отдельного HF backend. APRS и DSP/ANC не интегрированы.
- Нет live GNSS, AX.25 RX/TX, NR/NB/notch, тем/редактора цветов, battery gauge
  или постоянного сохранения настроек. Эти функции не скрыты в работающем меню.
- NOR firmware read-only; RAM сбрасывается. Калибровки сохраняются byte-for-byte.
  CPS 0.3.1 умеет локальное редактирование/экспорт и TXT-отчёт; native UI проверен.
  Изменение файла не является RF-калибровкой или записью в станцию. C-01..C-06
  остаются отдельной линией работ; совместимость нового Rust runtime с полной
  stock CPS не подразумевается.
