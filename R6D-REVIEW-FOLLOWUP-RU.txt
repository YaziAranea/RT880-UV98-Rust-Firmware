ЗАДАЧА
1. Воспроизвести до изменения production. Исправить переход целиком:
   запрос -> pending restore -> подтверждённые bin/frequency -> Listen.
   Либо явно заморозить pending selection, либо атомарно закрепить подтверждённый
   bin/frequency при BeginListen. Реальный callback из main должен использовать
   ровно тот путь, который проверяют App/UI+Scope тесты. При смене API regression
   перенести на новый production callback, а не удерживать устаревшую сигнатуру.
2. Проверить стрелки и repeat между запросом/ACK; MENU/overlay; второй Listen/
   Accept при pending; EXIT/PTT/fault до ACK. Позднее завершение отменённого
   действия не включает Listen, не переписывает VFO и не запускает TX.
   После входа displayed frequency == подтверждённый RxRequest.frequency_10hz;
   индикатор аудио truthful. До ACK не показывать состоявшееся прослушивание.
   После EXIT прежний полный RX-план восстанавливается, sweep возобновляется
   только по существующему контракту; release/new-edge guard не ослаблять.
3. Тесты должны выполнять новый реальный переход, не вручную выставлять
   listening=true до ввода (так пропущена ошибка r6d). Сохранить все старые
   DS regressions. Добавить кадр pending Listen и проверку confirmed после стрелок.
4. После targeted PASS — один полный итоговый прогон, отдельный r6e каталог,
   BIN/ELF/source ZIP и SHA, журнал и короткий R6E-REPORT-RU.md. Исходные r6d
   артефакты не перезаписывать. Итоговые исходники должны совпасть с source.zip.
5. Уточнить документы: r6d не прошёл независимую приёмку DS-06. В PROGRESS
   раздел Open questions всё ещё содержит закрытые кодом утверждения про
   unmapped sidekey / saved-effective power; заменить актуальными статусами,
   отдельно сохранив отсутствие live-проверки. Не терять остальные требования.
