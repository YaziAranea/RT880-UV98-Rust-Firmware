DS-10 / CODE TRACE, ЕЩЁ НЕ ЗАПУЩЕН ROOT INTEGRATION REGRESSION
Идентичность окна отсутствует у Listen/AcceptVfo. Request несёт только bin;
main проверяет scope.plot.valid(bin) новой сетки, пока UI показывает старую.
Успешный Restart не очищает старый snapshot. App::set_spectrum349..366 штатно
возвращает false при pending_rows.any, оставляя его на экране.
Пример: центр433MHz, шаг12.5kHz, 81точка -> bin0=432.500MHz.
После сужения до41точки новый bin0=432.750MHz. Новая точка0 уже измерена,
но новый snapshot ещё не принят UI. Listen/AcceptVfo со старого графика
передают0; backend восстанавливает432.750MHz вместо видимых432.500MHz.
Это затрагивает и прослушивание, и явное принятие частоты в VFO.

Сначала воспроизвести интеграционным тестом App+Scope:
- старый snapshot и cursor0, не дренировать render_step;
- реальный restart Scope в меньшее окно, дождаться valid0;
- App отказывает публикации нового snapshot из-за pending_rows;
- UI MENU->Listen/Accept формирует запрос;
- пройти тот же production coordinator/validation, что вызывает main;
- при разрешённом действии confirmed RxRequest.frequency_10hz обязана
  совпадать с выбранной отображённой частотой, иначе явный отказ ДО retune/commit.
Повторить span/step changes, stale completion прошлого сеанса, отказ restart.
Решение: связать selection с session/window identity + частотой и проверять
против текущего Scope, либо явно блокировать selection до публикации нужной
сетки. Только valid(bin) и совпадение bin в ACK недостаточны.

КОНТРАКТ И ПРОВЕРКА РЕАЛЬНОЙ СВЯЗКИ
Не добавлять очередной независимый bool без описанных переходов. Минимальную
логику согласования запроса, опубликованного окна, RF completion и UI phase
выделить в тестируемый coordinator, ИСПОЛЬЗУЕМЫЙ main. Существующий
spectrum_flow.rs можно расширить; отдельный поток/RTOS/большая архитектура
не требуются. Snapshot графика и текущее управление не должны спорить за phase.
App::confirm_spectrum_listen сейчас возвращает Result<(),...> и проглатывает
Controller false; отчёт r6e ошибочно обещает false наружу. Сделать явный результат
принято/отклонено с нужной identity; main учитывает отказ до включения Listen/
audio profile. Это дефект контракта; отдельный достижимый RF-case root пока
не подтвердил. Не выдавать его за уже воспроизведённую передачу/опасный RF.
