# Сначала бэкап, потом прошивка

> **ПРЕ-АЛЬФА — экспериментальная прошивка и CPS.** Проект находится на очень ранней стадии, ещё до альфа-версии. Возможны ошибки, потеря работоспособности и повреждение станции. Решение об установке и всё использование — полностью на ваш страх и риск. ПО предоставляется как есть, без гарантий; авторы не несут ответственности за ущерб или убытки в соответствии с условиями лицензии. До установки прочитайте лицензию и инструкции резервирования и возврата на сток.

[На главную](../README.ru.md) · [English](GETTING-STARTED.en.md) · [Deutsch](GETTING-STARTED.de.md)

Эта инструкция — для первой подготовки UV-98 Plus / исследованной RT-880. **Сначала читаем данные со стока. Прошивку выбираем только после проверки совместимости.** Резервирование можно выполнить отдельно, не устанавливая Rust-прошивку.

## 1. Подготовьте станцию и папку

1. Зарядите аккумулятор. Подключите кабель программирования к компьютеру и рации.
2. Включите рацию **обычным способом, без PTT**. Должен появиться штатный экран частот или каналов. Чёрный экран с зелёным LED — режим загрузчика, для чтения он не подходит.
3. Штатной программой для своей модели прочитайте станцию и сохраните исходный `.880dmf` или `.98pdmf`. Если уже есть `999.880dmf`, оставьте оригинал неизменным.
4. Закройте штатную CPS, Radio Tuning Software и другие программы, использующие кабель. Перед первым чтением нашей CPS выключите рацию на 3 секунды и снова включите обычно.
5. Создайте папку, например `Документы/UV98-backup-2026-11-16`. Внутри удобно сделать подпапки `01-original`, `02-calibration`, `03-nor`, `04-settings`, `05-recovery`. Положите исходный файл CPS в `01-original`.
6. Распакуйте [комплект R38 с CPS 0.7.0](https://github.com/YaziAranea/uv98-rust/releases/download/r38/UV98-r38-2026-11-16.zip) целиком. Запустите `UV98-CPS.exe`, выберите **Русский** в списке **Язык / Language / Sprache**, затем откройте **«Резервные копии»**. Выберите фактический COM-порт через **«Обновить список» → «Доступные порты»**. COM20/COM21 из старых инструкций не обязательно ваш порт.

Список языков всегда виден на панели. Все восемь вкладок и уже показанные сообщения меняют язык сразу. Несохранённые правки остаются в формах, а выбор языка запоминается в профиле Windows. Заголовки и фильтры файловых диалогов следуют языку CPS, стандартные кнопки — языку Windows. В комплект R38 входит выпущенная сборка CPS 0.7.0.

Запишите в простой текстовый файл модель станции, версию стока и известную ревизию платы. Держите этот файл рядом с резервами.

## 2. Выполните три чтения

Каждый раз сначала выбирайте нужную подпапку кнопкой **«Папка для снимков…»**. CPS сама создаст внутри отдельный каталог `UV98-read-…`. Сохраняйте его целиком.

| Порядок | Кнопка в CPS | Что должно появиться |
|---|---|---|
| 1 | **Считать калибровки (4 КиБ)** | `calibration.bin` — **4096 байт**. Индивидуальные заводские данные именно этой станции. |
| 2 | **Считать память настроек (4 МиБ)** | `storage-address-space.bin` — **4194304 байта**; дополнительно отдельный `calibration.bin`. Полная доступная внешняя NOR-память. |
| 3 | **Считать каналы, настройки и калибровки** | `calibration.bin`, `cfg.bin`, `channels.bin`, `zones.bin`, `fm.bin`. Удобные отдельные секции. |

Второй пункт самый долгий. Дождитесь **обоих проходов**, не нажимайте кнопки рации и не меняйте её настройки во время чтения.

После **каждой** операции должно появиться:

> Два чтения совпали. Снимок и журнал сохранены. Порт закрыт.

Не удаляйте `manifest.json`, `started.json` и файлы `pass-*.bin`: они входят в снимок. В `manifest.json` успешного чтения должны быть значения:

```json
"status": "verified_two_reads",
"two_reads_byte_identical": true
```

Само наличие файла `.bin` ещё не означает успешный бэкап. При ошибке, отмене или несовпадении чтений не переходите к прошивке. Сохраните неудачный снимок, устраните проблему кабеля/порта и выполните новое чтение в новую папку.

## 3. Проверьте и сохраните комплект резервов

- Проверьте размеры `calibration.bin` и `storage-address-space.bin` по таблице.
- Сверьте SHA256 `calibration.bin` в манифестах первого и второго чтения: заводской блок должен совпасть. Если нет — сначала разберитесь с чтением.
- Сохраните подходящий **заводской файл прошивки** отдельно в `05-recovery`. Публичный комплект Rust не содержит прошивку производителя. Для исследованной платы используйте указанный ниже проверенный источник 1.16; для другой ревизии сначала подтвердите совместимость.
- Скопируйте всю папку резервов ещё в одно место: другой диск, флешку или собственное защищённое хранилище. Личные дампы в публичные GitHub issues не загружайте.

У вас должны остаться:

| Сохранённое | Для чего |
|---|---|
| Исходный `.880dmf` / `.98pdmf` | Каналы и настройки в формате штатной CPS. |
| Проверенный `calibration.bin` | Индивидуальные заводские калибровки. |
| Проверенный `storage-address-space.bin` | Внешняя NOR-память целиком в доступном протоколу диапазоне. |
| Папка отдельных секций и все журналы | Сравнение, диагностика и подготовка копии настроек. |
| Подходящий заводской BIN | Возврат штатного приложения MCU через загрузчик. |

**NOR 4 МиБ — не дамп MCU и не копия загрузчика.** В известном штатном протоколе нет команды чтения этих областей. Кнопка сохранения заводского BIN копирует предоставленный вами файл из папки `recovery`, а не считывает прошивку вашей рации. Поэтому этот набор нельзя называть полным побайтовым клоном всех микросхем станции.

Чтение секций само по себе **не создаёт новый `.880dmf`**. Для этого в CPS нужно открыть свой исходный файл, применить считанные секции и сохранить отдельную копию. Секция `Time` останется из исходного файла; калибровки хранятся отдельно. Для обычного резервирования этот дополнительный шаг не нужен.

### Где взять файл возврата на сток

Для исследованного профиля сохранён stock 1.16: [страница файла в архиве nicsure](https://github.com/nicsure/RT880-FlasherX/blob/915545ae89f4a7547f6cea37408a5ba1d48e21f6/RT-880_Upgrade_V1_16_250915.bin) · [скачать BIN](https://raw.githubusercontent.com/nicsure/RT880-FlasherX/915545ae89f4a7547f6cea37408a5ba1d48e21f6/RT-880_Upgrade_V1_16_250915.bin). Размер — **251904 байта**, SHA256:

```text
eaef215cc7084dcd94281bbffb7ab6e2dd1e79ce135f01c90e3dbc691dd16bfc
```

Поместите файл с именем `RT-880_Upgrade_V1_16_250915.bin` в папку `recovery` рядом с `UV98-CPS.exe` (создайте папку, если её нет). Теперь кнопка **«Сохранить заводской BIN 1.16…»** сможет сделать отдельную копию; CPS проверяет SHA. Можно также выбрать этот исходный BIN напрямую во вкладке «Прошивка». Не заменяйте файл другой версией под тем же именем.

## 4. Проверьте совместимость перед прошивкой

R38 рассчитана на исследованный профиль платы AT32F423. Перед записью проверьте ревизию платы. Подготовка по бэкапу привязывает образ к вашим калибровкам.

Для подтверждённой совместимой платы подготовьте персональный BIN. **Компилятор Rust не нужен.**

1. В нашей CPS откройте **«Прошивка»**. Выберите исходный `UV98-r38.bin` из текущего комплекта.
2. Нажмите **«Подготовить образ для моей рации…»**.
3. Выберите **`manifest.json` полного снимка 4 МиБ NOR**: из папки, полученной кнопкой «Считать память настроек (4 МиБ)». Нужен именно манифест, а не сам `storage-address-space.bin`. Снимок только калибровок здесь не подходит.
4. Выберите папку для новых образов, например `Документы/UV98-personal`. CPS создаст внутри новый каталог `UV98-personal-…`.
5. Дождитесь успешной подготовки. Получатся `firmware/UV98-personal.bin` и `firmware/catalog.json`; новый BIN автоматически будет выбран для прошивки.
6. Сохраните всю созданную папку. Если позже снова откроете CPS, выберите `UV98-personal.bin` вместе с лежащим рядом каталогом.

CPS проверяет статус двух чтений, размеры и SHA файлов снимка, совпадение калибровочного блока с началом NOR а также исходный шаблон по каталогу выпуска и маркеру профиля калибровок. В новый BIN записывается только ожидаемый **SHA ваших калибровок**, а не сами калибровочные данные. Исходный BIN и резерв не меняются. После запуска прошивка сравнивает этот SHA с реальными калибровками станции.

У персонального BIN свой SHA, записанный в новом каталоге CPS. Храните BIN вместе с каталогом и используйте резерв своей станции.

Если подготовка отказала, проверьте, что выбрали полный успешно сверенный снимок своей станции и исходный BIN R38 из того же комплекта. Используйте исходные манифест и каталог, чтобы проверка работала.

Переходите дальше только при успешной подготовке, подтверждённой совместимости платы и наличии проверенных резервов и подходящего заводского BIN в двух местах.

## 5. Запишите совместимый образ

1. Распакуйте весь комплект: CPS проверяет BIN по `firmware/catalog.json`, поэтому одиночного файла рядом со случайной старой CPS недостаточно.
2. В CPS откройте **«Прошивка»** и выберите подготовленный `UV98-personal.bin`. Проверьте имя и SHA256 на экране; CPS сверяет их с новым персональным каталогом.
3. Выключите рацию ручкой. Зажмите **верхнюю PTT**, включите и через 2–3 секунды отпустите PTT. На исследованной станции загрузчик показывает чёрный экран и зелёный LED.
4. Выберите COM-порт кабеля. Отметьте подтверждение готовности загрузчика и нажмите **«Записать прошивку»** один раз.
5. Дождитесь явного сообщения о завершении. Во время записи не выключайте рацию, не вынимайте кабель и не закрывайте CPS.
6. После завершения выключите рацию на 3 секунды и включите **без PTT**. Проверьте экран, клавиши и приём. Сохраните журнал операции.

**Выбор языка:** MENU → СИСТЕМА / TX → ЯЗЫК / LANGUAGE. Стрелками ↑/↓ выберите РУССКИЙ, ENGLISH или DEUTSCH; MENU подтверждает, EXIT отменяет. После выключения язык пока возвращается к русскому.

По умолчанию верхняя PTT запрашивает передачу по A, нижняя — по B. Во время передачи красная рамка и отметка TX появляются на фактически передающей карточке независимо от выбранной строки. Текущая мощность каждого слота хранится в RAM и после включения стоит на LOW. Значок батареи показывает до четырёх делений примерного уровня и напряжение с шагом 0,1 В (`--.-V`, если показание недоступно). [Данные по нижней PTT](../research/r37/ptt.md)

Подтверждения загрузчика означают, что файл передан. Запуск и работу проверяйте на самой рации. Опорная версия владельца — R33. Для R38 предстоит проверить индикацию TX, нижнюю PTT, показания батареи, работу CB/КВ и приём MDC1200 внешним декодером. [Данные и границы проверок R38](../research/r38/EVIDENCE-RU.md)

### Сетка CB

1. Откройте **MENU → КАНАЛЫ / VFO → СЕТКА CB**. При первом открытии после включения выбран канал **15 AM, 27,135 МГц** в сетке из 40 каналов («пятёрки»).
2. Выберите канал стрелками ↑/↓ или введите номер **1–40**. Нажмите MENU, чтобы настроить VFO A. Клавиша `#` переключает «пятёрки» и «нули». Канал 15 на «нулях» — **27,130 МГц**. Клавиша `*` меняет AM/FM. В AM доступен только приём. Передача в FM проходит штатные проверки TX.
3. Для быстрого входа откройте **MENU → КНОПКИ → ДОЛГИЕ КЛАВИШИ**, нажмите нужную цифру, выберите **СЕТКА CB** и подтвердите MENU. С главного экрана удерживайте назначенную цифру.
4. Удерживайте EXIT на экране сетки, чтобы выйти из CB и вернуть прежний контекст VFO A. VFO B работает независимо. Последний подтверждённый выбор CB доступен до выключения.

### MDC1200 и локальное имя

1. На главном экране выберите A или B. Удерживайте `*` для переключения между слотами. Откройте **MENU → GPS / СИГНАЛЫ → MDC1200** и проверьте букву слота в заголовке.
2. В **РЕЖИМ MDC** выберите **ВЫКЛЮЧЕН**, **В НАЧАЛЕ TX**, **В КОНЦЕ TX** или **В НАЧАЛЕ И КОНЦЕ TX**. По умолчанию режим выключен. Подтвердите MENU.
3. В **UNIT ID** введите четыре шестнадцатеричных знака от `0001` до `DEEE`. Нажимайте 0–9 для цифр, удерживайте 1–6 для A–F. Клавиша `*` удаляет символ, MENU принимает, EXIT отменяет. Чтобы очистить ID, подтвердите пустое поле.
4. В **ИМЯ (ЛОКАЛЬНО)** нажимайте цифру несколько раз для перебора символов. Перед второй буквой на той же клавише нажмите ↑. Клавиша `#` меняет RU/EN, `*` удаляет символ. MENU сохраняет до 12 символов, EXIT отменяет правку.

Пакет MDC1200 передаёт PTT-ID. Имя служит подписью на этой рации. Режим, ID, имя и другие настройки прошивки действуют до выключения и хранятся в RAM. [Кадр редактора имени](images/r38/ru-mdc-alias-ru.png)

## 6. Если нужно вернуться на сток

Закройте другие программы. Снова включите штатный загрузчик верхней PTT и в нашей CPS выберите **подходящий заводской BIN**. Запишите его тем же порядком и включите станцию обычно после завершения.

На исследованном устройстве запись приложения MCU не перезаписывает внешние каналы и калибровки. **Перепрошивка стока не восстанавливает уже повреждённую NOR.** Наша CPS пока не записывает сырой 4-МиБ дамп или калибровочный блок обратно в рацию. Если повреждены именно они, нужен отдельный план восстановления по вашим сохранённым файлам; их нельзя выбирать как файл прошивки MCU.

| Проблема | Следующее действие |
|---|---|
| COM-порт занят или не открывается | Закройте все CPS. Переподключите USB кабеля, обновите список и выберите фактический порт. |
| Чтение не прошло | Проверьте обычный запуск стока. Повторите в новой папке; предыдущий снимок сохраните. |
| Запись оборвалась | Сохраните журнал. Снова включите загрузчик и повторите запись подходящего полного BIN. После начала стирания обычный запуск может не работать до успешной записи. |
| Новый образ не запускается | Верните известный подходящий сток через загрузчик. Не стирайте NOR и не меняйте калибровки наугад. |
| Загрузчик не появляется | Остановитесь и приложите к отчёту модель, версию, шаги и журнал. Не перебирайте случайные BIN. |
