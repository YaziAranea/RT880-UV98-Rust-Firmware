UV98 Rust: GPIO-драйвер, запуск подготовленного RX, RSSI и звук
2026-11-08

Результат этапа

Добавлен реальный код работы с GPIO AT32F423 под opt-in feature hardware.
Он собран для Cortex-M4, но на пользовательской рации не запускался.
Runtime связывает прежний план настройки с запуском RX, чтением RSSI и
управлением FM-аудио. Готового образа для прошивки устройства ещё нет.

Драйвер crates/rf-at32

GPIO-владение разделено без изменения прежнего API дисплея/NOR/клавиатуры.
ReservedPins::with_rf потребляет GPIOF и выдаёт отдельные неповторяемые
владения для RF A, RF B и управления антенной/звуком:
  A: PA8 CS, PF6 SCK, PC9 DATA;
  B: PC7 CS, PC8 SCK, PC6 DATA;
  PF0 — запрос положения антенного реле; PF8 — управление аудио.
PB6 PTT остаётся у клавиатуры; PC15/PB11 TX-линии этот драйвер не меняет.

Аппаратные конструкторы требуют предварительно проверенной платы и
неактивного RF/TX. DATA сначала освобождается, затем уровни загружаются
перед включением выходов. Изменяются только выделенные поля GPIO;
SCR/CLR используются вместо записи всего выходного порта. Участки RMW
должны быть сериализованы с остальными пользователями того же порта.
Новый порядок подготовки держит CS HIGH; он не копирует стоковый boot CS LOW.

PF8 LOW соответствует стоковому mute-request, HIGH — audio-request.
Для HIGH и переключения PF0 требуется внешний observational interlock.
LOW остаётся доступен для аварийного запроса mute. Это запрос GPIO, не
измеренное подтверждение напряжения/звука или физического RF-off.
Interlock не имеет разрешающей реализации по умолчанию: нужны свежий PTT,
проверенные PA/питание/clock/ownership условия. Пины PTT не дублируются.

Runtime crates/receive/src/runtime.rs

Вход: неизменяемый проверенный Plan и отдельно подготовленный RF-контекст.
Порядок: initial interlock/A33 TX-check -> внешний mute -> A47=6040 ->
семь операций плана -> A37=1F0F -> номинальные10мс -> A30=0200 -> A30=BFF1.
Это новая композиция подтверждённых стоковых фрагментов, не cold-init.

Время отсчитывается только от свежего монотонного миллисекундного clock.
Первый вызов после записи устанавливает консервативную точку начала задержки;
время самой записи не вычитается из новой минимальной выдержки.
Поддержан u32 wrap, ограничены интервалы/тайм-ауты; equality означает timeout.
10мс восстановлены по SysTick-алгоритму стока. Электрические тайминги шины,
контактов реле и PLL этой величиной не подтверждаются.

После запуска требуется явный acknowledge_settled для текущего Ticket
и завершение минимальной выдержки. Старые/ранние ACK не продвигают состояние
и не продлевают deadline. Один прошедший таймер не создаёт готовность.
Поставщик ACK обязан иметь независимое основание считать RX стабильным;
автоматического аппаратного детектора PLL-lock в этом этапе нет.

Только после Listening разрешены:
- sample: A67 & 0x01FF, сырой RSSI без dBm; squelch — A0C bit1.
  При level0 squelch-open возвращается без чтения0C. Стоковый global monitor
  override сюда не переносится. После чтений interlock проверяется повторно;
  обнаруженный PTT/отказ не позволяет опубликовать устаревший результат.
- open_fm_audio: внешний mute -> A47=6140 -> чтение полного A01 ->
  скорректированное слово громкости A48 -> открытие внешнего gate.
  Громкость рассчитывается из CFG gain0..63/DAC0..15 по стоковой формуле.
- mute_audio: PF8 LOW и A47=6040.

Открытие звука явное; автоматическая политика squelch/monitor остаётся за
приложением. Modulation FM не выводится из CPS-поля RX/TX operation mode.
RSSI и полный runtime для чипа B не заявляются: stock caller не подтверждён.

Ошибка сохраняет причину, этап и отдельную ошибку mute cleanup. После ошибки
или stop дальнейшие обычные запросы запрещены, повторный start не разрешён.
Cleanup делает один запрос внешнего mute, не пишет через неисправную RF-шину
и не объявляет PA отключённым. Drop активного runtime также один раз пытается
закрыть звук; явный stop нужен для проверки ошибки. Idle/terminal Drop инертен.
Stop необходимо вызывать и после завершённого одиночного sweep, независимо
от того, вернул ли spectrum engine Action::Cancel.

Проверено

  ./build-rx-runtime.ps1

273 Rust-теста, включая18 runtime и9 GPIO/сквозных; 25 Python-тестов.
ARM-сборка с uv98-rf-at32/hardware прошла. Независимое ревью без блокеров.
Сквозной host test исполняет PinEngine -> RF Bus -> Pair -> Runtime:
настройка, explicit ACK, RSSI/squelch, FM volume, открытие звука и stop.
Регистрные кадры получаются из GPIO-событий, а не подменяются готовым планом.
Проверены ошибки каждого префикса, PTT между чтением/записью, delayed-first-poll,
устаревшие ACK, deadline equality, wrap, отказ mute и отсутствие повторов.

Новые stock oracle:1024 RSSI,96 squelch,512 audio-mode,36 FM sequences,
2 RX-start,18 PF8 fragments,3 clock profiles. Код и CSV в research/rx-runtime;
SysTick COUNTFLAG в эмуляторе подставлялся, реального времени это не измеряет.
Источник — родственный RT880 1.16 BIN, не считанный MCU данной UV98.
Подробные отчёты: validation/rx-runtime-build-summary.json,
rx-runtime-verification.json, research/rf-hardware/EVIDENCE-RU.txt.

Граница готовности и продолжение

Stage0 по-прежнему WFI; новый код не включён в его boot entry. Не выполнены
cold RF initialization, аппаратная проверка ревизии, шины/clock/PTT и полный
вывод звука/реального спектра на UI. Следующая связка — board bring-up и
интеграция runtime с главным циклом, кнопками и spectrum ticket protocol.
Для физического запуска отдельно нужен подтверждённый путь восстановления
MCU/bootloader. NOR-бэкап4МиБ таким MCU-бэкапом не является.

COM и устройство в этом этапе не использовались. Исходные заводские
калибровки, NOR и999.880dmf сохранены. CPS0.3 и прежние архивы не заменены.
Пакет локальный; сохранённая calibration fixture включена для повторения тестов.
