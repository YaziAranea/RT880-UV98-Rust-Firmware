CB И «800 MHz»

В R33 коммутация уже подключена к действующему executor, а старый отчёт
research/band-switch/EVIDENCE-RU.txt описывает незавершённый ранний этап.
rf-sequence::receive начинает с mute/PA-off, затем после настройки пишет
A33 и PF0. Runtime ждёт ещё 10 ms перед состоянием Receiving. TX сначала
гасит предыдущий тракт, меняет PF0, затем через delay10ms включает PA.
Стоковые калибровочные записи и поправки применяются отдельно для частоты.

Частота RX     A33 & 0x33   PF0/K200 запрос
27.135 MHz    0x0001       HIGH, HF/CB
145.500 MHz   0x0010       LOW, VHF
433.500 MHz   0x0020       LOW, UHF
850.000 MHz   0x0002       HIGH, U8

Это одно механическое K200 плюс электронные ключи; VHF/UHF не требуют
отдельного щелчка. Название режима «800» не означает частоту 800.000 MHz.
Штатная CPS RT-880 V1.10, декомпилированный MainForm.cs:
- строка 4766: WorkRange = 64-620MHz / 18-64MHz / 840-1000MHz;
- 12211 / 12746: значение хранится в CFG[116];
- 11519 / 11545: CheckFreq отвергает 660 <= MHz < 840;
- 6097: калибровки U8 начинаются с 840-920MHz.
SHA256 MainForm.cs:

Исходник локально: ../cps-analysis/rt880-v110-decompiled/DM550_NOLCD/MainForm.cs
относительно родительского work/ каталога.

Сток 1.16 selector 0x08012A30 подтверждает RX route5 для 840..1300MHz;
новый UI ограничивает ввод 999.99999MHz. Функции 0x08004B88/0x08003CCC
пишут частоту плюс заводская поправка в 0x38/0x39, без скрытого конвертера
800->840. См. research/frequency/EVIDENCE-RU.txt и независимые oracle CSV.
SHA256 reference BIN eaef215cc7084dcd94281bbffb7ab6e2dd1e79ce135f01c90e3dbc691dd16bfc.

У fagci порог800 отличается от стока:
https://github.com/fagci/rt880-fw/blob/main/src/driver/bk4819.c
getBand выбирает 30/240/800MHz. Переносить этот порог без собственной
калибровки нельзя: в заводском selector для800.000 запись не выбрана.
Поэтому новый быстрый CB/800 preset должен выбирать 27.135/850.000MHz,
а фактическую коммутацию оставлять существующей частотной политике.
CB AM пока RX: AM TX в production не реализована; FM TX отдельный режим.

Добавлен интеграционный тест повторных CB->V->U8->U->CB переходов,
проверяющий финальные A33/PF0, выключенный PA и отсутствие stale-кэша.
Старые корректные таблицы маршрутов не переписывались ради видимости правки.
Щелчок реле/чувствительность/реальная RF-полоса требуют проверки владельцем.

КВ ВОДОПАД

Новый radio-runtime::shortwave_scope::Sweep использует один существующий
Session Si4732. 32 последовательных подтверждённых отсчёта; AM шаг5kHz,
USB/LSB/CW1kHz, WFM100kHz. Окно ограничено рабочими границами UI, не
перескакивает через пределы тюнера. Точная пользовательская частота/BFO
не переписывается и возвращается при отключении обзора.

request(selected, enabled) -> Tuning; observe(requested, Update) -> Sample.
Каждый вызов обычного Session.tick выполняет одну короткую фазу I2C.
Нет цикла полного sweep, искусственного шума и дублирования старых отсчётов.
Перестройка центра начинает новую строку. Отсчёты приходят лишь после
STC и подтверждения частоты либо штатного Quality ответа той же настройки.
Аудио во время обзора закрывает coordinator: один Si4732 не может сохранить
непрерывное аудио прежней частоты, одновременно перестраиваясь по диапазону.
При выходе звук открывается только после Tuned исходной частоты.

Это RSSI-водопад по последовательным частотам, не аудио FFT. SSB-шаг1kHz
задаёт сетку обзора; обычная точная настройка50/100Hz через BFO сохранена.
Полный проход не выдаётся за мгновенный спектр. Физическая скорость зависит
от STC/loop; аппаратного замера в этом этапе нет.

ИСПРАВЛЕНИЕ SI4732

При быстрой смене желания AM->FM ранее TuneStatus/ReadQuality могли брать
opcode/длину ответа из нового режима, хотя незавершённая команда относилась
к старому. Теперь формат определяется фактически отправленным Tuning.
Результат старой настройки по-прежнему не публикуется как новая частота.

DSP, БЕЗ ВЫДУМАННОГО PCM

В Session добавлен Processing: AM фильтр6/3/1kHz; переключатель SoftMute
одновременно включает 100Hz фильтр сетевых помех и максимум8dB мягкого
подавления по SNR. Выключение ставит attenuation0 и отключает high-pass.
Свойства Si4732 0x3102 и0x3302, по одному SET_PROPERTY с CTS/deadline.
Профиль не применяется к SSB patch/WFM. Это встроенная цифровая обработка
тюнера, не broadband NR, не импульсный NB, не подавление шума на основном BK.
Первичный источник: Skyworks AN332, 2024-10-29, стр.94 и99:
https://www.skyworksinc.com/-/media/Skyworks/SL/documents/public/application-notes/AN332.pdf
Кнопки и подписи должны говорить «фильтр AM / SoftMute», а не обещать AI NR.

BK4819 EARO по имеющейся схеме идёт в аналоговый AF тракт. Поток PCM для
MCU, ADC->DMA->DSP->DAC и отдельно управляемый ANC в конкретной плате
не установлены. Нельзя подменять DSP переключением PC3: PC3 выбирает вход
микрофона и уже участвовал в дефекте пропавшего TX-голоса. См. radio018/GPS-...
Требование полного NR/NB остаётся открытым до доказанного аудиотракта.

СИГНАЛИНГ: RUNTIME API

signaling_read/write открывают только47/50/70/71/72 в Transmitting,
проверяют владельца GPIO и readback, при ошибке исполняют общий shutdown.
signaling_microphone меняет только REG30 bit1 для замены речи тоном.
Внешняя библиотека тонов не получает произвольный доступ к RF/power/route.
Перед обычным снятием TX caller возвращает сохранённые регистры и микрофон.

Authorization::tail_configuration_valid проверяет неизменные контекст,
частоту, субтон, мощность, биндинг, выбранный слот, экран/lock/scan после
отпускания. Он не означает физическое удержание и не разрешает новый TX.
Coordinator обязан ограничить конец передачи коротким deadline, старым TOT
и отменять на любое новое нажатие/ошибку. Повторное армирование отдельно.

ПРОВЕРКА

Добавлены целевые сценарии sweep/возврата/краёв, обработки AM/неприменения
к SSB, смены pending mode, readback failure и TX whitelist, tail context.
Исполнение Cargo/ARM/полная интеграция выполняются root и отражаются в
общем verification.json. Этот файл сам по себе не утверждает PASS или
аппаратную работоспособность нового водопада/фильтров/сигналинга.

РУЧНОЙ APRS: КООРДИНАТОР

firmware-diagnostic/src/beacon.rs принимает один явный запрос с действительным
GPS fix и конфигурацией APRS. До RF проверяется текущий FM TX-план по исходным
калибровкам. C-BUS модем инициализируется до включения PA; packet start идёт
только после фактического состояния Runtime::Transmitting.
После готовности модема требуется непрерывно200ms закрытого carrier SQL.
Проверяется squelch_open, не audio_open: чужой CTCSS/DCS не делает канал
свободным. Нужны RX+TX профиль и фактическая настройка именно этого RX.
При SQL0 канал считается занятым. Общий deadline5s включает ожидание;
авторетрай отсутствует. PB4-high показывает неподдерживаемый backend.
Новая клавиша/PTT, уход со страницы, смена профиля и ошибка отменяют пакет,
возвращают PB7 и останавливают RF. Основной цикл сбрасывает applied RX cache
после завершения, чтобы действительно возобновить приём. Внешний modem audio
идёт через штатный MIC ADC, поэтому DTMF-отключение MIC здесь не применяется.
Уровень модема берётся из существующей CFG. Декодированный приём пакета другой
станцией не проверялся: программное окончание передачи не доказывает доставку.
