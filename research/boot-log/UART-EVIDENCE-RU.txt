USART6 НЕ имеет отдельного переключателя на HICK
-----------------------------------------------
src/at32f423_usart.c:119..217, usart_init:
  USART1/2/3 выбирают PCLK/SCLK/LEXT/HICK через crm_usart_clock_get;
  USART6 явно использует clocks_freq.apb2_freq.
src/at32f423_crm.c:651..704, crm_usart_clock_select/get:
  switch содержит только CRM_USART1, CRM_USART2, CRM_USART3.
inc/at32f423_crm.h:506..508 подтверждает этот enum.
Поэтому нельзя объявлять кабельный UART независимым от смены PLL/APB2.

Rust читает CTRL/PLLCFG/CFG/MISC1/MISC2 дважды, требует равенства снимков
и совпадения запрошенного/активного источника. Известны только HICK и PLL
от HICK. HEXT отклоняется: частота кварца данной платы не угадывается.
Формулы из src/at32f423_crm.c:923..997:
  HICK = 8 MHz; 48 MHz только при MISC1.HICKDIV && HICK_TO_SCLK;
  затем /2^MISC2.HICK_TO_SCLK_DIV, допустимо 0..4;
  PLL = 8 MHz * NS / MS / 2^FR / 2;
  AHB/APB2 используют таблицы делителей из того же SDK.
Для PLL проверяются NS31..500, MS1..15, FR0..5, вход2..16MHz,
VCO500..1000MHz, HICKDIV, lock/enable и номинальный SYSCLK <=150MHz.
Для HICK8MHz это дополнительно ограничивает MS значениями1..4.
DIV = round(PCLK2 / 115200): 8MHz -> 69, 48MHz -> 417.
Отклоняются DIV<16 и номинальная погрешность baud >2%.

Перед сменой clocks каждый успешный кадр ждёт TDC (пуст и shift register).
Во время initialize() кадров нет. После полного либо частичного перехода
Rust повторно определяет APB2 и настраивает USART. Неизвестные/нестабильные
clocks означают отсутствие журнала, а не разрешение продолжить запуск.
Pre-RAM ASM имеет отдельный ограниченный распознаватель clocks; его точный
набор профилей и linked-image тесты описаны в документации diag-startup.

Регистры: отдельные GPIO-поля, только PA11
----------------------------------------
CRM=40023800: AHBEN1+30 bit0 GPIOA; APB2EN+44 bit5 USART6;
APB2RST+24 bit5 — локальный reset USART6. Остальные биты сохраняются.
GPIOA=40020000: CFGR PA11=AF(10), OMODE PA11=push-pull,
ODRVR PA11=moderate(10), PULL PA11=none, MUXH PA11=AF8.
При активной блокировке PA11 конфигурация GPIO/UART не меняется.
USART6=40011400: STS+00 TDBE bit7, TDC bit6; DT+04; BAUDR+08;
CTRL1+0C=0x2008 (UEN+TEN); CTRL2+10=0; CTRL3+14=0.
Режим 115200 8N1, без RX, IRQ, DMA, flow control, inversion и half-duplex.
UART RX data register не читается; командный приёмник не существует.

UART допускается после family gate (SERIES_REVISION & FF00)==1200.
Это разрешение только на журнал. Строгие ProductID/revision/flash-size
проверки startup перед GPIO/RF остаются отдельными и не ослабляются.
Неизвестное семейство: никакой записи в периферийные регистры UART.

Владение и границы
-----------------
crates/boot-log: Frame, ClockSnapshot, Logger<RegisterIo>, RawMmio, TxLogger.
Формат ровно47 байт ASCII:
  UV98D1 CCCCCCCC AAAAAAAA BBBBBBBB DDDDDDDD*SS\r\n
SS — сумма modulo256 первых42 ASCII-байтов до '*', uppercase hex.
C — код события, A/B/D — три32-битных поля. Проверка целостности не является
аутентификацией; повреждённые и частичные строки не считаются событиями.

Logger по умолчанию48 попыток кадров; допустимый верхний предел64 на объект.
Лимит ожидания8192 чтения STS на один флаг; общий предел65536 на кадр.
Каждая попытка кадра расходует бюджет. Timeout и clock drift блокируют
дальнейшую передачу данного Logger, без автоматического восстановления.
Ни один logger не кормит, не включает, не отключает watchdog. Время ожидания
ограничено итерациями, не обещается физический предел в миллисекундах.
Сторожевой таймер всё ещё может сбросить CPU посреди кадра.

Временный RawMmio используется только после инициализации RAM, до получения
PAC ownership, с IRQ masked и исключительным доступом к USART6/PA11.
После выхода из этого scope TxLogger получает USART6 и BootLogPins(PA11).
PA12 остаётся ReservedAfterBootLog. Общие GPIO/CRM RMW сериализованы.
Нет retained global mutable logger, нет записи в Drop. Терминальный путь
может выполнить отдельную конечную попытку после невозвратного отказа от
всех прежних владельцев; он не продолжает их использование.

Проверки, предусмотренные исходным кодом
--------------------------------------
Host unit tests: wire/checksum, clock decode/rejection, family/pin-lock
guards, сохранение чужих GPIO/clock bits, whitelist всех MMIO writes,
отсутствие RX reads, полный TDC drain, TX timeout, timeout final drain,
общий предел polling на кадр, исчерпание бюджета без его сброса,
clock drift и изменившийся снимок. Положительный тест проверки family
не подразумевает разрешение неподдерживаемой ревизии для RF.
ErrorText/tests и интеграция main подготовлены основным агентом.
Итоги Cargo/linked-image тестов фиксируются отдельно основным агентом.
