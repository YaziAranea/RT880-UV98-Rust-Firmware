Канал CPS: проверенная раскладка и границы реализации

Источник: статическая декомпиляция RT-880 CPS_V1_10_250806.exe, ILSpy 8.2.
SHA256 EXE: b2533229c783c86150a4230a8a51c5ee274092e9f1b036bbb7a5b511c34dabd6
Основной исходник: ../rt880-v110-decompiled/DM550_NOLCD/MainForm.cs.
EXE не запускался, устройство и COM-порты не использовались.

Файл .880dmf содержит секцию Channels с позиции 0x1000, длина 0xC000.
Секция состоит из 1024 записей по 48 байт. Эти смещения относятся к файлу.
Разметка записи, относительно её начала:
  0: режим модуляции; сохраняется без изменений.
  1: R+T=0, RX=1, TX=2. Это отдельное поле, не sentinel частоты TX.
  2: запись отображается CPS при точном значении 1. Патчи её не активируют.
  3: Wide=0, Narrow=1; весь байт.
  4..5: RX tone, u16 little-endian.
  6..9: RX frequency, u32 little-endian.
  10..13: TX frequency, u32 little-endian.
  14..15: TX tone, u16 little-endian.
  16: Low=0, Medium=1, High=2; весь байт. Мощность в ваттах не установлена.
  17: TX priority; сохраняется без изменений.
  18: TOT / CTDC; сохраняется без изменений.
  19: бит7 исключает канал из scan; биты0..6 относятся к scramble/tail.
  20..31: три поля mute-code; сохраняются без изменений.
  32..47: имя, GBK, padding FF.

Ссылки на методы:
  SaveSingle, строка11214: запись полей; byte2=1, полная пересборка18/19.
  SetChInfo, строка11784: чтение, присутствие byte2==1.
  cboxRXTX, строка7299: R+T, RX, TX, порядок0/1/2.
  SaveCHName, строка10944: GBK и FF padding.
  CopyArrayToString, строка10779: остановка на первом FF.
  SaveSubaudio, строка11729 / SetSubaudio, строка11754: тоновые коды.
  CheckFreq, строка11493: ограничения UI, а не подтверждённая RF-спецификация.

Частота: SetChInfo выводит code/100000 MHz с пятью знаками после точки;
SaveSingle убирает точку. Одна кодовая единица соответствует10Hz для обычных
положительных частот. Кодек хранит u32 без изменения и без диапазона RF.
Оригинал использует Int32, поэтому некорректные старшие биты могут дать
отрицательное отображение CPS. Отображение таких значений не копируется.
CheckFreq допускает [18,660) и[840,1000)MHz. Эти UI-ограничения не доказывают
аппаратную поддержку диапазонов и не включены в низкоуровневый кодек.
Признаки TX-disabled через 0 или FFFFFFFF в исследованных обработчиках
не найдены. Проверенное представление RX-only: byte1=1, частота TX отдельная.

Канонические тоновые слова:
  None: 0000.
  CTCSS: 1000 | tenths_hz. Например88.5 ->885 ->1375.
  DCS normal: 2000 | code. D023N -> октальное023 ->десятичное19 ->2013.
  DCS inverted: 3000 | code. D023I ->3013.
Поле CTCSS12-битное; это предел хранения, не перечень поддержанных тонов.
DCS_NO содержит512 меток D000..D777, то есть code0..511.
Оригинальный SetSubaudio имеет более свободную проверку inverted-слов.
Наш decoder принимает только канонические слова; неизвестные остаются raw.
Encode отклоняет переполнение, не обрезает его маской.

Lossless API:
  Channel::parse / channel: заимствованное представление, никакой нормализации.
  patch_record / patch_channel: меняют только явно заданные поля.
  Незапрошенные байты и неизвестные значения сохраняются побайтно.
  scan_add меняет только бит7, сохраняя остальные7бит байта19.
  operation_mode/width/power заменяют свой байт; tone заменяет своё u16.
  При ошибке весь патч отклоняется до первой записи в память.
  Патч не активирует/удаляет канал, не меняет калибровки, не обращается к радио.
  padded_name отклоняет >16байт; исходный CPS молча обрезал GBK, рискуя
  разделить многобайтный символ. Кодирование/валидация GBK остаются в host UI.
  name_bytes останавливается на FF, но сохраняет NUL. Оригинальный CPS
  дополнительно удаляет NUL при отображении; raw API этого не делает.

Проверки: синтетические записи, точные смещения, сохранение остальных байтов,
все256 вариантов scan-байта, все65536 сырых тоновых слов, границы индексов,
отказ без изменений при неверном тоне, сохранение соседних каналов.
Это программные проверки; радиостанция и RF-поведение не проверены.

Воспроизводимость:
  python work/cps-analysis/channels/derive_channels.py
Скрипт читает только уже декомпилированные тексты, сохраняет source-excerpts.cs.txt
и channel-evidence.json с хешами и сравнением методов UV98 CPS.
Пути к исходникам можно передать через --rt-source и --uv-source.
