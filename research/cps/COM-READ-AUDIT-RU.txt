Последовательность транспорта, фактически успешная на COM20
  115200 baud, 8 data bits, no parity, 1 stop bit.
  DTR=true, RTS=false; xonxoff/rtscts/dsrdtr=false.
  Python задаёт DTR/RTS до port.open(); нельзя случайно принять иные defaults.
  CONNECT: 34 52 05 10 9B; ожидаемый ответ один байт06.
  Reader допускает максимум3CONNECT с timeout200ms; 00 допускается для повтора,
  любой другой ответ отвергается. Фактические успешные полные сеансы: одинCONNECT.
  READ(block): 52 hi lo sum8; hi/lo — big-endian u16 номер1024байтного блока.
  sum8 = сумма предыдущих байтов по модулю256, не CRC.
  Ответ: 52 hi lo +1024байта data +sum8, всего1028байт.
  Проверять точную длину, все3байта header/address и sum(frame[0..1027])&255.
  Чтение может приходить частями; reader собирает ровно1028 с общим deadline3s.
  Write timeout1s, пауза между блоками20ms. Частичный write — ошибка.
  После ACK сеанс завершается END: 34 52 05 EE 79; отдельного ACK не ждёт;
  ждёт20ms, закрывает порт. Даже при read error делает bounded END/close.
  Между двумя независимыми проходами: close/reopen и пауза200ms.
  Нет command0x2A (установка времени), opcodes записи40/90..A3, flash/erase.

END caveat — сохранять точную формулировку
  CONNECT не обнуляет dirty guard20001225 и backup kind20001227.
  READ не меняет эти флаги и не вызывает запись.
  END08024788..C0 при уже установленном guard может вызывать копирование:
    kind1: calibration0x0000..0x0FFF ->backup0x1000..0x1FFF;
    kind2: CFG/Channels/FM primary ->соответствующие externalSPI backups.
  Проверенные ветки стирают/программируют externalSPI, не MCU flash.
  Исходное состояние guard после power-on и все побочные ветки не доказаны.
  Корректно: «Клиент не отправляет явных команд записи/стирания».
  Некорректно: «Сеанс гарантированно не делает никаких физических записей».
  Equal images доказывают стабильность прочитанных значений; перепрограммирование
  тех же байтов не исключается. Не заменять END неизвестной последовательностью.

Рекомендации live-read CPS0.2
  1. Один явно выбранный порт и один worker. Без автооткрытия/автоперебора портов.
     UI заранее показывает чтение; не переходить в bootloader/update mode.
     Перед первым trial проверить питание/обычный режим радио и отсутствие
     другого активного CPS/Tuning-сеанса. При ошибке занятости не убивать процесс.
  2. Полностью фиксированный allowlist: CONNECT,184известных READ,END.
     Никакой синхронизации часов, изменения baud, writes/defaults/config reset.
     Одна outstanding request; timeout,wrong address,checksum,shortwrite ->stop.
     Не искать следующий header внутри повреждённого payload; ошибка sum8 — stop.
  3. Два прохода с отдельным reopen; сначала проверить length/header/checksum,
     затем побайтовое равенство блоков. До этого не менять Document.
     Если значения реально изменились — сохранить evidence и показать mismatch.
  4. Cancellation между блоками либо bounded read deadline; cleanupEND/close
     после подтверждённогоCONNECT. Не закрывать приложение до завершения worker.
     Перед CONNECT не отправлять END наугад; failedACK не даёт verifiedsession.
  5. Сохранить attemptedTX,rawRX,validatedframes,blockorder,timestamps,hashes,
     ошибки/частичные данные и отдельно provenance непрочитанногоTime.
     Не публиковать partial как verified; старые backup/исходныефайлы не заменять.
  6. Применение verifiedsnapshot к существующему чистому документу — явнойкнопкой,
     atomic transaction; только прочитанные4секции. Undo возвращает исходное.
     Текущие калибровки0..3 при обычномCPS READ не запрашиваются/не заменяются.
