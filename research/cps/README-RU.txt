Доказательства офлайн-кодека CPS
==============================

Здесь сохранены результаты статического разбора предоставленных CPS:
RT-880 CPS 1.10 и UV98 Plus CPS 1.07. Это исследовательские снимки, а не
отчёт о текущей готовности приложения. Актуальные результаты сборки, GUI,
export/undo и проверки пользовательского файла находятся в validation/ проекта.

Состав
------
triage.json / triage.py
  Карта файла 221184 байта, сравнение 15 обработчиков двух CPS, хеши исходников
  и методов. Форматы .880dmf и .98pdmf совпадают в исследованных обработчиках.
CPS-PLAN-RU.txt
  Исходный статический triage: layout, источник каждого диапазона протокола,
  ограничения обычного READ и планы дальнейшей работы. Фразы о ещё не созданном
  UI относятся к моменту triage, не к поставляемому приложению.
channels/
  Раскладка 48-байтной записи, тоны, частоты, scan-бит, режим RX/TX, raw GBK;
  JSON с точными ссылками и хешами, скрипт извлечения и ограниченные выдержки
  восьми обработчиков. Полная декомпиляция CPS не включена.
settings/
  Поля CFG, зоны и 32-байтные FM/receiver-записи: смещения, допустимые коды,
  источники строк, различия между raw и проверяемыми setters. source-refs.txt
  содержит выбранные строки доказательств, не целый файл исходника CPS.
corpus/
  Только метаданные трёх существующих файлов: размер, SHA, секционные хеши,
  агрегированные сравнения и скрипт проверки. Данные каналов не включены.
  999.880dmf обозначен последним сохранённым 2026-11-08 по сообщению пользователя;
  это не доказательство свежести Time. Сами файлы остаются у пользователя.
evidence-manifest.json
  Список 12 скопированных исследовательских файлов и проверенные SHA256.

Воспроизведение
---------------
Исходные EXE и полные декомпиляции намеренно отсутствуют. Скрипты читают только
заранее полученный C# текст, не загружают/не запускают CPS и не открывают COM.
Для повторения нужны собственные локальные статические декомпиляции ILSpy 8.2;
сначала сверить SHA исходных EXE/MainForm.cs с triage.json и channel-evidence.json.

triage.py ожидает относительно своей папки:
  rt880-v110-decompiled/DM550_NOLCD/MainForm.cs
  ../uv98-cps-decompiled/DM550_NOLCD/MainForm.cs
Также сравнивает ReadForm.cs, WriteForm.cs, PortForm.cs, NewFileForm.cs,
DesClass.cs из тех же папок. Эти частные входы не нужно включать в дистрибутив.

Для канальных доказательств пути можно задать явно:
  python channels/derive_channels.py --rt-source <RT_MainForm.cs> --uv-source <UV_MainForm.cs> --output <новая_папка>
Для инвентаризации собственных сохранённых CPS-файлов:
  python corpus/inspect_corpus.py --output <новый_отчёт.json> <файл1.880dmf> <файл2.880dmf>
Скрипт не выводит имена/частоты каналов и не изменяет входные файлы. Сообщённую
пользователем дату последнего сохранения он не выводит из байтов автоматически.

Ограничения
-----------
Это доказательства формата и сохранения байтов, не физической RF-совместимости.
Time хранится непрозрачно; обычный READ исследованных CPS его не заполняет.
Файл CPS не содержит полного образа MCU, загрузчика и заводских калибровок.
Описание WRITE в triage не означает реализацию либо разрешение записи в радио.
Офлайн-приложение не включает serial transport.
