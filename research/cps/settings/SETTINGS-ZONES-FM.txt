Implemented scope
-----------------
No-std borrowed views and narrow in-memory edits in the codeplug crate:
src/settings.rs, src/zones.rs, src/fm.rs. No serial, device access, allocation,
defaults or reserialization. Unknown bytes and original field values are exposed
unchanged. Failed edits change no bytes. Section parsers check exact length only.
Names are opaque GBK-encoded bytes; no UTF-8 conversion is performed by the crate.
Editing the fixed name field intentionally replaces/pads only that field.

The 13 corresponding tests cover exact changes, untouched headers/tails/adjacent
records, invalid sizes/indices/codes, offset-binary BFO and opaque encoded names.
The parent agent runs Cargo; these tests are synthetic mapping/preservation tests,
not execution of CPS or physical validation on UV98 Plus hardware.

Zones: section length 131072 = 256 * 512
----------------------------------------
Per-record offsets:
  +0,+1     Two raw count bytes. See anomalous write below.
  +2..+3    Opaque, preserved.
  +4..+19   16 encoded name bytes (GBK with FF padding in CPS save).
  +20..+419 200 LE16 member codes.
  +420..511 Opaque, preserved; not an extension to 246/250 supported members.

DataToPanel reads names at12028..12032 and all200 member LE16 words at12081..12088.
Even though bufZoneListRight is allocated [256,250] at2246, the init/read/save/UI
loops examined consistently use200. SetSelectList at15314..15347 stores zero-based
channel indices i, while user-visible fallback names print i+1.
Channel codes0..1023 reference the 1024 channel slots; sentinelFFFF is used by
InitZoneList11979..11985 and remove logic15576..15581. Other codes remain raw.

SaveData name encoding/padding/truncation is12905..12927. It counts entries<1024,
writes all200 words, then writes (byte)count to BOTH +0 and +1 at12938..12939.
Do not silently reinterpret that as a standard LE16 count. Zone::cps_count_bytes
returns both original bytes. set_member_code changes only its two member bytes.
refresh_cps_count is a separate explicit operation matching those two CPS writes;
it does not repair unknown member codes, compact gaps or touch bytes2/3/tail.
The count is a number of stored references, not a verification that channels exist.

ResetSelectedList15350..15392 removes missing/invalid channels and compacts its
UI-side membership array. The Rust library deliberately does not reproduce those
lossy UI normalization steps during parsing or unrelated edits. Duplicate indices
also remain untouched; no claim of a complete zone consistency validator is made.

FM/receiver channels: section length4096 = 128 * 32
-------------------------------------------------
Per-record offsets:
  +0        Range code: CPS save emits0..3.
  +1        Demodulation code: FM=0, AM=1, LSB=2, USB=3, CW=4.
  +2        Step index. CPS save searches0..6; UI displays0..7 (see below).
  +3        Bandwidth index0..5.
  +4        ATT index. CPS save searches0..5; UI displays0..38 (see below).
  +5..+6    LE16 offset-binary BFO: displayed integer = raw - 32768.
  +7..+8    LE16 frequency code (not a universal physical frequency unit).
  +9        CPS present marker: exactly1 means display this record.
  +10..+15  Opaque, preserved.
  +16..+31  16 encoded GBK name bytes, normally FF padded.

SaveFMCHName11380..11403, ClearSingleFMCH11405..11410,
SaveSingleFM11412..11484, SaveAllFMChannel11487..11494,
SetFMChInfo11871..11918 establish these fields.
GBK/UTF8 encoders are initialized at1577/1579. CopyArrayToString10779..10790
stops at the first FF and fills the rest with NULs; display removes NULs. Raw
accessors preserve those bytes. Name setters reject>16 bytes, avoiding CPS's
unconditional truncation that can split a GBK character.

Frequency read formatting in SetFMChInfo:
  Range0 -> raw/100 with2 fractional digits; label "64-108 MHz".
  Range1 -> raw/1000 with3 fractional digits; label "2.0-30.0 MHz".
  Range2/3 -> integer raw; labels "520-1710 KHz", "153-279 KHz".
  Labels are declared at8084. Save removes the decimal point before truncating
  integer into LE16 at11445..11448. The library exposes raw frequency_code only;
  it does not convert units or silently truncate a larger physical input.

BFO UI min/max are -32767/+32767 at8009..8010. Save adds32768 at11473,
then writesLE16 at11475..11476. Read subtracts32768 at11912. bfo_value preserves
the full raw decoding, including raw0 -> -32768; set_bfo_value rejects-32768 to
match the UI range. set_bfo_code permits every raw u16 without normalization.

CPS inconsistencies retained as limitations:
- Step control8058 contains8 labels: 1K,5K,10,50K,100K,500K,1M,9K.
  SaveSingleFM11449 only searches j<7. Rust checked setter supports0..6.
- ATT control8024..8030 contains39 labels: AGC,0,-1,...,-37.
  SaveSingleFM11465 only searches j<6. Rust checked setter supports0..5.
- Bandwidth control8044 has6 labels: 0.5 K,1.0 K,1.2 K,2.2 K,3.0 K,4.0 K.
- Read displays FM whenever range==0 OR demodulation==0 (11880).
  Raw range and demodulation remain independent and unchanged in Rust.
- Marking a record present sets only byte9 to1. This is not initialization or a
  guarantee that its other fields form a valid receiver record. No clearing or
  default record creation is exposed here.
