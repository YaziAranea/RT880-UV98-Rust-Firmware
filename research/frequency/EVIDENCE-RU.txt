Частотные калибровки: подтверждённый алгоритм связанной RT-880 1.16

Источник: RT-880_Upgrade_V1_16_250915.nicsure.bin, 251904 байта.
SHA256 eaef215cc7084dcd94281bbffb7ab6e2dd1e79ce135f01c90e3dbc691dd16bfc.
База загрузки для статического разбора: 0x08002800.
Это публичный образ RT-880, НЕ считанный из пользовательской UV-98 Plus.
Совпадение аппаратной ревизии и всей прошивки не установлено.

1. Частотная поправка: один u16 на запись диапазона

Функции 0x08003CCC и 0x08004B88 сначала вызывают 0x08012A30 с исходным
частотным кодом. Их второй аргумент selector равен соответственно 1 и 0.
Затем обе читают u16LE из RAM 0x20003064, то есть первые два байта выбранной
112-байтовой записи калибровки.

  corrected = (frequency_code + raw_offset - 32768) mod 2^32
  reg38 = corrected & 0xFFFF
  reg39 = corrected >> 16

Доказательство:
  0x08003CDA..3CE0 — load u16, add, subtract 0x8000;
  0x08003CE4..3CF0 — передача low/high в регистры 0x38/0x39,
                     через helper 0x0801E6D4;
  0x08004B96..4B9C и 4BA0..4BAC — тот же алгоритм, helper 0x0801E660.

Поправка не зависит от позиции внутри выбранного диапазона. Интерполяции,
масштабирования поправки по частоте и насыщения результата здесь нет.
Единица модели — целочисленный код стока. Это не измерение ошибки в герцах
и не утверждение о фактической точности радиочастоты.

2. Выбор записи и позиции таблицы

Функция 0x08012A30 проверяет диапазоны в указанном ниже порядке.
Обе границы включены, сравнения беззнаковые. Побеждает первая проверка.

  lower      upper       origin      slot
  13600000   17400000    13500000       0
  40000000   48000000    40000000       1
   1800000    6400000     1500000       2
   6400000   13600000     6000000       3
  17400000   24000000    17000000       4
  24000000   32000000    24000000       5
  32000000   40000000    32000000       6
  48000000   56000000    48000000       7
  56000000   66000000    56000000       8
  84000000   92000000    84000000       9
  92000000  100000000    92000000      10
 100000000  108000000   100000000      11
 108000000  116000000   108000000      12
 116000000  124000000   116000000      13
 124000000  130000000   124000000      13

  temporary_index = u8(floor((frequency_code - origin) / 500000))
  table_index = min(temporary_index, 15)
  record_offset = 32 + slot * 112

Деление UDIV и UXTБ присутствуют в каждой ветке; ограничение 15 расположено
в 0x08012D3A..12D3E. Для перечисленных окон преобразование к u8 не обрезает
полезные биты, но модель сохраняет последовательность операций стока.
Далее идут обычные LDRB по индексу; интерполяции соседних точек нет.

Особенности сохранены буквально:
  - 13600000 и 17400000 попадают в slot 0; 40000000 и 48000000 — slot 1.
  - Промежуток строго между 66000000 и 84000000 не распознаётся.
  - Последняя ветка 0x08012CBE содержит bytes 0D 26: MOVS r6,#13.
    Здесь повторно используется slot 13. Slot 14 этот selector не выбирает.
    Причина неизвестна; заменять 13 на 14 как «исправление» нельзя.
  - На 124000000 остаётся прежняя ветка: slot 13, point 15 после ограничения.
    На 124000001 следующая ветка: slot 13, point 0. Это подтверждено эмуляцией.
  - Верхние частотные участки некоторых окон используют последнюю точку 15.
    Количество колонок в UI tuning-программы не заменяет этот алгоритм.

3. Откуда берётся запись; граница перенесённой логики

0x08012CE0 сравнивает slot с кэшем RAM[0x2000081A]. При совпадении запись
повторно не читается. При смене slot обновляет кэш и вычисляет 32+slot*112.
RAM[0x200010E9] выбирает источник:
  0: SPI main array, record_offset;
  1: SPI main array, 0x1000 + record_offset;
  2: встроенный ROM-образ по адресу 0x08028344 + record_offset;
  прочие значения: нового чтения нет, старый RAM-буфер остаётся.
SPI helper: 0x08025D30; копирование из ROM: 0x080081C4.
Источник и кэш подтверждены отдельными RAM-only сценариями эмулятора.

Если частотный код вообще не распознан, selector возвращается через
0x08012CDC без обновления записи/таблиц. Обёртки задания частоты после этого
всё равно используют старую поправку. Pure Rust API сознательно возвращает
None для отсутствующего выбора; скрытое использование старого кэша не переносит.
correct_code — отдельная арифметика с явно переданным raw_offset.
Автоматические значения по умолчанию, чтение SPI и состояние кэша не добавлены.

4. Табличные байты после выбора

Из record +0x10/+0x20 берутся две таблицы в RAM 0x2000081B/0x2000081C.
При аргументе selector mode=0 дополнительно читаются:
  +0x30 -> RAM 0x2000081D; +0x40 -> RAM 0x2000081F;
  +0x50 -> RAM 0x2000081E; +0x60 -> RAM 0x20000820.
При mode!=0 эти четыре значения не обновляются.
Названия power/noise/squelch согласуются с layout tuning-программы;
их дальнейшее применение и выбор wide/narrow исследует RF-модуль отдельно.
Selector также меняет два байта маршрутизации 0x20000838/0x20000839.
Они не включены в чистый API выбора калибровки: физический смысл не установлен.

5. Проверка реальными инструкциями, без устройства

derive_frequency.py использует общий stock_emu.py / Unicorn 2.1.4.
В эмуляторе отображены только Flash и RAM, периферия MMIO не отображена.
Загрузка всего firmware boot flow, serial и запуск host EXE не выполнялись.

  Selector: 694 случая с границами, точками деления, детерминированными
  случайными входами и mode=0/1. Оригинальный Thumb-код работает целиком;
  только SPI-read заменён выдачей синтетической 112-байтовой записи в RAM.
  CSV содержит наблюдавшиеся RAM slot, регистр point и адрес запроса чтения.

  Correction: 96 случаев, включая переполнение/заём и крайние raw_offset.
  Оригинальные две функции выполняют арифметику; selector заменён no-op,
  register helpers — записью аргументов в журнал RAM-only теста.
  CSV содержит наблюдавшиеся пары аргументов и собранное из них слово.

Дополнительно: источники 0/1/2/неизвестный 3 и повторный slot без чтения.
Ожидаемая формула сверена с машинным результатом; CSV записывает результат
машинного исполнения, а не заранее вычисленную ожидаемую формулу.
Эмуляция не проверяет электрическую часть, RF, тактирование и реальный UART.

python analysis/frequency/derive_frequency.py --skip-disassembly
Имя верхнего каталога analysis зависит от расположения подготовленного архива.
Без --skip-disassembly дополнительно формируется ограниченный дизассемблерный
листинг напрямую из BIN. Любой другой SHA256 исходника отвергается.
