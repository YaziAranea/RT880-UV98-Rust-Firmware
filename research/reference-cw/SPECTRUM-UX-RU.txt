2. Наблюдаемые приёмы, полезные для UV98

Область обзора отделена от частоты прослушивания.
[S1] GetStepsCount/GetScanStep/GetBW, UpdateScanStep, UpdateFreqChangeStep,
UpdateCurrentFreq, UpdateCurrentFreqStill; [S2] SpectrumSettings.
Есть 16/32/64/128 точек, шаг измерения, отдельный шаг сдвига окна и частота
detal/listen. Ввод частоты выделен в FREQ_INPUT с MENU для применения.
Идея полезна: zoom, pan и точная настройка — разные действия. Для UV98 не
копировать 16/32/64/128 буквально: наш bounded engine рассчитан на 81 точку.
У нас размах между первой/последней точкой равен (N−1)*step, не N*step.

Обзор умеет находить и слушать сигнал.
[S1] UpdateScan:1144–1167 выбирает максимум прохода, сравнивает порог,
ToggleRX(true) и TuneToPeak. UpdateListening:1180–1209 держит звук, затем
проверяет уровень и возобновляет сканирование. monitorMode обходит порог.
Это полезный цикл «обзор → обнаружение → слушать → продолжить», а не просто
индикатор столбиков. Настройки scan/listen bandwidth разделены в ToggleRX.
Наше перенесение идеи требует собственного полного RX restore/ACK,
подтверждённого звука и монотонных дедлайнов, без копирования регистров.

Есть отдельный детальный режим STILL.
[S1] OnKeyDown:871–874: PTT открывает STILL и настраивает найденный peak.
OnKeyDownStill:985–994: EXIT закрывает редактор регистров либо возвращает
SPECTRUM; монитор выключается, обзор запускается заново. В STILL стрелки
тонко меняют частоту. Но PTT для TX там только TODO, строки 972–975!
Нельзя описывать этот исходник как готовый spectrum-to-TX режим.
Для UV98 полезно отдельное прослушивание без потери исходного окна;
назначение PTT переносить нельзя — сохраняем нашу глобальную отмену.

Шкала и порог видимы и управляемы.
[S1] Rssi2PX/Rssi2Y, DrawStatus, DrawRssiTriggerLevel, DrawTicks, DrawNums:
подписаны min/max, шаг/число точек/границы, есть частотные риски, отметка
центра и пунктирный порог. UpdateDBMax меняет верхнюю границу; dbMin
обновляется по минимуму измерений. Это информативнее неподписанной сетки.
Rssi2DBm использует rssi/2−160+dBmCorrTable[Band] — это формула/таблица UV-K5,
не калибровка UV98. У нас сначала только RAW с явными min/max; никаких dBm/S
по перенесённой формуле. Автомасштаб не должен незаметно менять смысл высоты.

Peak — конкретный найденный сигнал, а не неопределённая декоративная линия.
[S1] PeakInfo и UpdatePeakInfo:426–428 запоминают частоту/уровень/индекс;
более сильный максимум либо возраст >=1024 scan steps заменяет peak.
DrawArrow/DrawF показывают именно его. rssiHistory — профиль последних
замеров, не водопад и не массив независимых исторических пиков каждого bin.
Для UV98 отдельно назвать «Сильнейший сигнал» и «Удержание пиков»;
уже имеющийся Plot.peaks подходит второй функции, не следует их смешивать.

Есть исключение постоянной помехи.
[S1] Blacklist/IsBlacklisted/ResetBlacklist; Side1 исключает peak,
смена сетки очищает список. ENABLE_SCAN_RANGES дополнительно меняет хранение.
Идея пригодится после базового listen/restore. У нас явный bitmap пропусков
сбоку от valid/fresh, не sentinel RSSI=65535 и не перезапись реального замера.

3. Что не копировать
- 128×64 monochrome-компоновку, микрошрифт 3×5 и глобальный framebuffer.
- Карту всех цифровых shortcuts: 1/7 шаг, 2/8 pan, 3/9 шкала, 4 число точек,
  5 ввод, 0 modulation, 6 bandwidth, * / F порог. Без подсказок её трудно
  обнаружить; она конфликтует с назначаемыми долгими цифрами нашей UI.
- MENU как no-op в обзоре и редактор сырых LNA/PGA/IF-регистров в STILL.
  Пользователь просит понятное быстрое меню и явное подтверждение выбора.
- Блокирующий while в APP_RunSpectrum и preventKeypress, который способен
  откладывать ввод до конца прохода. У нас EXIT/PTT обслуживаются между
  ограниченными операциями, независимо от отрисовки и публикации snapshot.
- Неограниченное ожидание register 0x63 в GetRssi:317–319, паузы20/100ms
  в обработчиках клавиш. Для нашего UI это регресс отзывчивости.
- Автоматическое изменение громкости/AGC/RF-path, таблиц bandwidth, GPIO,
  калибровок, AM compensation или dBm без собственного аппаратного основания.
- RestoreRegisters как достаточное доказательство полного восстановления
  UV98. Наша модель требует полного нормального RX и отдельного ACK.

4. Предложение UV98: единый режим «Обзор сигнала» — ЕЩЁ НЕ РЕАЛИЗОВАНО

Контекст сеанса
Вход из выбранного A/B сохраняет неизменяемый Origin: slot, MR/VFO,
частоту/канал, reverse, zone, modulation и подтверждённые RX-настройки.
Второй слот показывается только как сохранённый контекст, не dual RX.
Grid: center_10hz, step_10hz, N=81, start=center−40*step,
end=center+40*step, span=80*step. Все81 точка обязаны пройти RF/calibration
валидацию. Нельзя молча обрезать диапазон или перескочить на другой тракт.
Неподходящий запрос остаётся draft с понятной причиной; старый grid сохранён.
Числа в UI вычисляются из подтверждённой grid, не из неподтверждённого draft.

Состояния и смысл
PREPARING → SWEEPING ↔ LISTENING; EDITING — интерфейс черновика;
RESTORING → Home/предыдущий обзор; ERROR — отдельный явный исход.
PREPARING/RESTORING не предлагают «Слушать» до ACK. Неизмеренный bin
отмечен «ещё нет замера», неизвестное не равно нулю. ERROR не рисует RX.
Прослушивание требует остановить sweep и полностью настроить нормальный RX
на cursor, включая фильтр/звук. Только ACK включает надпись «СЛУШАЕМ».
Возврат возобновляет ту же grid, отмечая старые данные и новый номер прохода.

Понятное управление
- ↑↓: cursor на один bin, удержание — штатный bounded repeat.
- MENU: компактный список до7 строк: «Слушать/Обзор», «В VFO A/B»,
  «Центр», «Шаг и размах», «Шкала RAW», «Пики», «Сильнейший сигнал».
  Список стабилен по странице, выбор требует MENU; EXIT отменяет draft.
- #: быстрый переход в «Шкала RAW». Варианты:0..511 и явно подписанные
  увеличенные окна. Сначала ручной масштаб; будущий AUTO фиксируется по
  завершённому проходу, с видимыми границами и без дрожания каждый bin.
- «Шаг и размах»: при81 точке два параметра зависимы. Выбор step показывает
  вычисленный span; выбор span предлагает совместимый step и точные границы.
  После MENU backend сначала проверяет grid, потом перестраивает её.
- «Центр»: числовой draft или «поставить курсор в центр». Для pan доступны
  сдвиги ±полокна; это отдельная команда, не скрытая побочная работа стрелок.
- «Пики»: показать/скрыть и явный сброс. «Сильнейший» перемещает cursor
  только на измеренную точку текущего прохода; не на старый hold автоматически.
- «В VFO A/B»: явное назначение в выбранный слот, после restoreACK.
  Второй слот и исходный MR-канал не меняются без такого подтверждения.
- Долгое * (обычное A/B): завершить текущий сеанс с restore исходного RX,
  затем выбрать другой слот на Home. Не менять владельца работающего sweep
  молча. В Spectrum оба сохранённых контекста не означают два приёмника.

EXIT и PTT — сохраняем пользовательский общий смысл
- EXIT в draft закрывает draft без применения; если одновременно слушаем
  или MON активен, сначала прекращает это временное действие.
- EXIT в LISTENING: выключить временный MON/звук, вернуться в прежний обзор
  только после подтверждённой перенастройки; второе EXIT завершает сеанс.
- EXIT в SWEEPING: восстановить Origin и Home. Долгое EXIT из любого
  вложенного экрана выполняет весь путь отмены сразу. Никакой записи NOR.
- PTT из Spectrum прекращает временный режим и восстанавливает Origin;
  это нажатие не передаёт. Дальнейший TX требует release и нового нажатия
  уже в обычном режиме. Политику CW/STILL другой рации сюда не переносим.
Нюанс «один EXIT сразу Home» против двухшагового выхода из LISTENING должен
быть окончательно согласован root с общим контрактом красной EXIT до кода.
В любом варианте первое EXIT немедленно отменяет временный звук/режим.

Данные и отзывчивость
Сохранить bounded81 Plot и один480B row; framebuffer не вводить.
Счётчик sweep и fresh bitmap дают видимый прогресс без выдуманных samples.
Snapshot — immutable после публикации. Изменение сетки очищает старые
измерения, пики и blacklist; разные grid никогда не смешиваются на экране.
Cursor обновляет карточку/маркер/readout, не полный график. Свежая grid
обновляется по dirty areas не чаще согласованной частоты2–5Hz; publish Hz
не объявляется частотой полного sweep. Показывать измеренную длительность
последнего завершённого прохода, если backend её действительно предоставит.
Нажатия обрабатываются между bounded RF/LCD-шагами, независимо от redraw.

Порядок реализации и проверки
1. Утвердить Origin/grid/state/request/ACK и точное EXIT/A-B поведение.
2. Привести renderer/симулятор к единой геометрии и состояниям, затем backend.
3. Сначала ручное listen/resume и center/step/span. Автозахват по порогу и
   исключение помех — отдельное дополнение после проверки базового цикла.
4. Host: valid0/unknown, 81edges, signed offsets, frequency overflow,
   failure/reject/restore/PTT, draft cancel, переключение A/B и преждевременный
   ACK; pixel oracle и input во время pending repaint.
5. Live: реальная частота и уровень известного сигнала, период sweep,
   cursor/EXIT, restore исходной станции и звук. Никаких выводов по PNG.
