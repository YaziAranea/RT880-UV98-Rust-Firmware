ПРОВЕРЕННЫЕ ПРИЁМЫ
1. src/main.c:7..27: клавиши обрабатываются перед Mode_Update; рисование
   вызывается при интервале >=16 ms. Это планировщик, не измеренные 60 FPS:
   update/render могут занимать дольше, а очередь клавиш ждать их завершения.
2. src/modes/mode.c:10..26: переключение режима отложено до Mode_Update,
   со старым exit и новым enter. Полезная модель владения RF/UI состоянием.
   В Rust у нас нужны дополнительно точные ACK/ticket и сохранение RxRequest.
3. src/ui/spectrum.c:201..259: сравнение старых/новых высот графика выделяет
   вертикальный диапазон изменившихся пикселей. Перерисовывается полная ширина
   этого диапазона, а не обязательно весь экран и не отдельный pixel на каждый bin.
4. Там же:239..255: два буфера строк; CPU готовит следующую строку, пока DMA
   передаёт предыдущую. Это полезный образец сокращения занятости CPU.
   Вся операция render при этом всё ещё содержит ожидания DMA; она не является
   готовым неблокирующим scheduler для PTT/клавиш.
5. Там же:262..306: waterfall строит одну цветную строку из RSSI history;
   вертикальное движение выполняется через scroll RAM дисплея. Не требуется
   переносить полный цветной framebuffer через MCU для каждого шага.
6. src/driver/st7789.c:344..357: используются VSCRDEF(0x33) и VSCRSADD(0x37).
   Область воды/строки выше неё могут разделяться. В нашей будущей версии
   постоянный нижний пояс тоже должен явно учитываться в геометрии.

ЧТО НЕЛЬЗЯ КОПИРОВАТЬ КАК ПРОВЕРЕННЫЙ ПРОФИЛЬ НАШЕЙ РАЦИИ
1. src/driver/st7789.c:55..109 использует SPI1, PB3/PB5 AF5 и DMA-request
   SPI1_TX. Наш stock trace и рабочий r5 используют SPI3/AF6, Mode0/Div2.
   Видимый рабочий экран r5 важнее предположения по имени чужой платы.
   Для DMA отдельно проверить request mapping SPI3_TX, владение каналом,
   параметры шины и последнюю передачу перед сменой D/C/CS.
2. src/driver/board.c:11..47 задаёт PLL-профиль с комментарием 150 MHz.
   Это не основание менять нашу clock tree или обещать такое ускорение.
3. st7789_dma_start/wait (174..193) возвращают void, в том числе после timeout.
   Наш интерфейс должен возвращать Result; нельзя отметить строки доставленными
   после timeout. Буфер занят до подтверждённого завершения/остановки DMA.
4. st7789_scroll_reset (360..372) меняет область и посылает NORON, но не
   устанавливает VSCRSADD в0. WF_Reset (spectrum.c:309..315) тоже не задаёт
   scroll-start. Это требует проверки; NORON сам по себе не считаем доказанным
   восстановлением координат. Результата на пользовательской станции нет.
5. Mode_Update делает enter, затем scroll_reset. Наш порядок восстановления
   должен задаваться явным контрактом, с правильным адресованием после EXIT,
   повторного входа, ориентации и ошибок транспорта.
6. Полный RGB565 240x320 framebuffer =153600 B. Его не планируем размещать
   в64KiB SRAM профиля AT32F423. Две строки240xRGB565 =960 B без служебных
   данных — потенциально подходящий размер, но RAM/stack проверяются в ELF.

КАК ПРИМЕНИТЬ В UV98 RUST — ПРЕДЛОЖЕНИЕ, ЕЩЁ НЕ КОД
А. Сначала исправить двойной RX restore и модель center/span/step/listen;
   отдельно хранить свежесть измерения и состояние прорисовки.
Б. Сузить damage графика; показывать пропуски, шкалу RAW и возраст sweep.
   UI не должен ждать полного нового обхода для движения курсора/EXIT.
В. DMA вводить отдельным ограниченным этапом: static line buffers с владением,
   непрерывный опрос клавиш/PTT, timeout/error, отсутствие повторного использования
   занятого буфера, полное завершение перед командами дисплея.
Г. Waterfall — опция после работоспособного графика. Строка = завершённый sweep;
   реальное время каждой строки сохраняется/показывается. Pause/listen не должны
   выглядеть как продолжение измерения; никакой искусственной временной шкалы.
Д. Для панелей без подтверждённого scroll оставить обычный график. Сравнить
   реальные времена loop, key-to-display, полного sweep и RX restore. Чужой
   интервал16 ms и DMA не считаются результатом такой проверки.

ПРОВЕРКИ ПРИ РЕАЛИЗАЦИИ
- Transcript: команды/байты/CS/D-C, границы scroll и reset при каждом выходе.
- Scheduler: клавиши/PTT обслуживаются при незавершённом DMA; ошибка доставляется.
- Image model: новый и старый график/курсор/шкала без следов и смешанных поколений.
- SRAM/stack и аппаратные тайминги измеряются отдельно; firmware SHA фиксируется.
- Калибровки/NOR остаются исходными; никакая аппаратная проверка сейчас не запущена.
