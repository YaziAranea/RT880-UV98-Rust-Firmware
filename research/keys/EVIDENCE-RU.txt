Матрица
-------
0x0801FA9C читает строки в порядке PC10, PC11, PC12, PD2.
Helper 0x080254DE возвращает 1, если запрошенный бит входа высокий.
Низкий уровень устанавливает бит raw, высокий сбрасывает.
Номер бита = column * 4 + row; u16 хранится в RAM 0x20001134.
Модель update_matrix принимает только Column C0..C3, сохраняет остальные биты.

0x0801FBA0 сначала считывает текущую колонку, затем выбирает следующую.
Колонки 0..3: PB10, PB2, PB1, PB0; цикл 0→1→2→3→0.
В traced stock выбранная следующая линия опускается; предыдущая поднимается.
Это сведения о стоке, НЕ операции Rust-crate. GPIO-write implementation нет.
Состояние текущей колонки — byte RAM 0x20001132.
Инициализация колонок/строк видна в 0x08011C7E..0x08011CEA.

Чистый decoder 0x08013084:
col0: bits0..3  → 1,4,7,*
col1: bits4..7  → 2,5,8,0
col2: bits8..11 → 3,6,9,#
col3: bits12..15→ Menu,Up,Down,Exit
Числовые stockcodes: цифры0..9, Menu10, Up11, Down12, Exit13, *14, #15.
Названия согласованы с опубликованной таблицей fagci; значения доказаны BIN.
Специальные raw aliases: 0x1111→14, 0x8888→15.
Все остальные комбинации, включая raw0, дают0xFF. 0xFF не доказывает,
что физически отпущены все кнопки: неизвестные комбинации дают тот же код.
matrix_key возвращает None, но исходный raw остаётся доступен вызывающему.
Нет предположения о подавлении ghosting, diode layout или одновременных кнопках.

PTT
---
0x080079B4 и0x0802228E читают GPIOB bit6 через helper254DE.
Вторая ветка при низком уровне устанавливает RAM0x20001127 в1.
Совпадает с PTTKEY в схеме и PIN_KEY_PTT в fagci/board.h.
ptt_pressed(false)==true. Key::Ptt и ButtonEvent — только входные факты.
В crate нет RF enable, TX action, TX GPIO, serial, flash, MMIO или unsafe.

Аналоговые вспомогательные клавиши
--------------------------------
0x080121E6..0x080121EA без масштабирования копирует ADC DMA u16
из RAM0x200010CE вRAM0x200010E6. Это НЕ соседнее battery вычисление.
0x08013D68 читает этот u16 и возвращает:
  0..1884    →0x17 (Aux17)
  1885..2716 →0x16 (Aux16)
  2717..3541 →0x18 (Aux18)
  3542..65535→0xFF
Функция проверена на всём u16 пространстве; реальные ADC значения могут иметь
меньший диапазон. Нет заявления о напряжении, физической кнопке или исправности
ADC при произвольном значении. Например, sample0 математически означаетAux17,
но это не диагностика короткого замыкания и не разрешение на действие.
0x08007982..0x08007998 сначала декодирует матрицу; ADC используется, если
matrixcode==0xFF. Полная стоковая политика клавиш/PTT не переносилась.
Физические названия Side1/Side2/Alarm для этих кодов пока не присвоены.

Энкодер и расхождение со сторонним кодом
--------------------------------------
На схеме CODE1/2-ADIN идут к выводам MCU9/8 и необязательному S500;
его общий вывод связан с землёй, линии имеют подтяжки к3V3.
Это не доказательство наличия энкодера на пользовательской плате.
Стоковая функция0x0801EADC конфигурирует PC0/PC1 alternate function7 и
периферию0x40005400. Поэтому присваивать PC0/PC1 обычным sidebuttons нельзя
только по чужому board.h. Stock consumer quadrature/direction не подтверждён.
EncoderLevels хранит только два уровня CODE1/CODE2, без направления/шагов.

Наша политика debounce
----------------------
Timing::new(debounce_ms,hold_ms) — явный выбор приложения, без Default.
Оба интервала1..2^31 ms, верхняя граница исключена.
Debouncer стартует Released. Изменение подтверждается после наблюдаемого
стабильного кандидата в течение debounce_ms. Это зависит от частоты sampling:
не увиденные между samples импульсы не могут быть распознаны.
Held отсчитывается от подтверждённого Pressed, выдаётся один раз.
Released выдаётся и после Held. Пока rawrelease ожидает debounce, Held подавлен.
Autorepeat отсутствует. Эти правила — наше UI-решение, НЕ перенос стоковых
таймеров/событий. Тестовые20/500ms — только параметры теста.
u32 clock wrap поддерживается. Между соседними samples требуется delta<2^31.
Backward/ambiguous time возвращает ClockError без изменения состояния.
Caller может игнорировать PTT в diagnostic; crate никогда не превращает его
в действие передатчика. На аппаратном уровне сигналы не тестировались.

Проверка и воспроизведение
-------------------------
oracle_keys.py использует общий research/stock_emu.py и Unicorn2.1.4.
Матрица иADC: все65536 u16 inputs, всего131072 bounded function calls.
Строки:256 случаев (4 seed patterns ×4 columns ×16 row-high masks).
Только для rows helper0x080254DE подменён бинарными значениями; каждый из
четырёх адресов/масок и порядок проверяются. Реальные peripherals не mapped.
Нет bootflow, COM, устройства или выполнения Windows EXE.

Пример из корня проекта, с отдельно предоставленными зависимостями/reference:
python research/keys/oracle_keys.py --reference PATH --deps PYTHON_DEPS_DIR
python research/keys/disassemble_keys.py --reference PATH --deps CAPSTONE_DIR
Также поддерживаются UV98_STOCK_REFERENCE, UV98_RESEARCH_DEPS;
oracle outputroot можно задать UV98_RUST_PROJECT (по умолчанию этот проект).
Reference hash проверяется до эмуляции и дизассемблирования.
Rusttests используют сохранённые CSV, не требуют reference/Unicorn/Python.
oracle-summary.json содержит SHA256fixtures и явные ограничения доказательства.
