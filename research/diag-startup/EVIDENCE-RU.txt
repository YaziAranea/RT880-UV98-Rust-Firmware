Диагностический AT32 startup, 2026-11-08

Область работ
crates/diag-startup содержит исполняемый ARM адаптер и модель последовательности
регистров. Аппаратный запуск, COM, прошивка, NOR/MCU write/erase не выполнялись.
Связанный профиль RT880 остаётся предположением для конкретной UV98 Plus.
PID идентифицирует вариант MCU; не плату, разводку, состояние RF или загрузчик.

Состав исходников
  src/pre_init.s — реальный __pre_init и __diag_terminal_fail_stop.
  src/hardware.rs — MMIO binding после RAM init; global_asm включает .s.
  src/lib.rs — чистая последовательность для повторного takeover/readback,
    watchdog policy, clock setup и CycleMillis.
  src/tests.rs — 13 host cases: identity/context, IRQ/master gates, GPIO masks
    и порядок latch→mode, LEXT и locks, watchdog rejection, clock ordering/
    timeout, 4 проверки cycle-counter arithmetic.
Тесты здесь не объявлены аппаратной проверкой. Итоговые build/test/emulation
логи сохраняет root integration; автор этого crate Cargo/build не запускал.

Почему __pre_init написан в assembler
Локальный cortex-m-rt0.7.7 src/lib.rs, строки305–308 и915–920, запрещает
Rust до RAM initialization: rvalue static promotion может обращаться к
статике даже без явного static в функции. Поэтому deprecated #[pre_init]
не используется и не подавляется. Cortex-m-rt Reset вызывает наш leaf ASM,
инициализирует .bss/.data, затем main вызывает Rust early_quiesce/initialize.
ASM использует только r0–r3, literal constants во Flash, MMIO; нет SP/RAM
доступов, push/pop, BL или вызовов Rust. LR сохраняется для bx lr.
Единственный обычный цикл ограничен 1..8 NVIC banks. Failure — WFI loop.
Core exception vectors должны прямо перейти в __diag_terminal_fail_stop,
без промежуточного Rust, поскольку fault/NMI возможны до .bss initialization.

Порядок ASM __pre_init
1. PRIMASK=1; IPSR=0 и CONTROL[1:0]=0 обязательны. Не пытаемся исправить
   exception/unprivileged/PSP entry. Валидный MSP обязан предоставить loader.
2. PID/series/revision/Flash allowlist. Нет GPIO на неподходящем PID.
3. SysTick CTRL/RELOAD/CURRENT=0; NVIC ICER/ICPR по ICTR (не более8 banks);
   clear PendSV/SysTick; VTOR=0x08002800; SLEEPONEXIT/SLEEPDEEP сняты.
4. DMA1/2 и OTG clocks gated, reset asserted. Каналы не включаются ради чтения.
   Это не GPIO reset; чужие GPIO поля и backup domain не сбрасываются.
5. LEXTEN=1 -> stop. PC14/PC15 могут принадлежать LEXT независимо от CFGR;
   выключения LEXT, backup reset или настройки ERTC здесь нет.
6. Только выбранные GPIO clocks. Проверка LOCK. Latch preload перед mode:
   PC15/PC4/PC5 LOW, PB11 LOW, PF8 LOW, PA4 LOW;
   PA8/PA15/PB12/PC7 HIGH (RF-A/LCD/NOR/RF-B CS), PC14 HIGH (LCD reset);
   PB0/1/2/10 HIGH open-drain (keyboard release).
   Push-pull outputs, no pull, drive2; все не принадлежащие маске bits сохранены.
   PF0 antenna relay не меняется. GPIO readback не является RF-off proof.
7. Только после CS HIGH SPI2/3 clocks gated/reset asserted. Их reset снимается
   Rust initialize после проверки clock profile, clocks остаются gated.
   Оба existing constructors также сбрасывают только свой SPI после clock enable.
8. DSB/ISB и return в cortex-m-rt для RAM initialization. Watchdog в ASM не
   меняется и не кормится; очень короткий inherited deadline может истечь здесь.

Терминальный ASM путь
__diag_terminal_fail_stop разрешён из handler mode: IPSR не проверяется.
PRIMASK, MCU allowlist, DMA/OTG gate+reset, LEXT/LOCK guards, те же четыре LOW
группы включая backlight. Никаких Rust/stack/.bss, затем WFI без reload WDT.
Нельзя возобновлять владельцев GPIO после этого пути. При ошибке identity,
LEXT или LOCK часть/все low requests могут не выполниться; не утверждаем off.
Неизвестная memory map может fault уже на чтении PID; это не универсальная
защита для произвольного MCU. PRIMASK не маскирует NMI/HardFault.

Clock profile после RAM initialization
Связанный stock1.16 SHA256:
  eaef215cc7084dcd94281bbffb7ab6e2dd1e79ce135f01c90e3dbc691dd16bfc
Основание: research/startup/EVIDENCE-RU.txt, clock-config.asm, clock_oracle.py.
HICK8MHz → PLL NS96/MS1/FR8/fixed2 =48MHz; AHB/1, APB1/2, APB2/1.
До switch выставлены stock FLASH_PSR0x154 и PWC1.3V. Auto-step включён,
HICK readiness проверена, direct HICK /16 + vendor settling, HICK selected
и подтверждён status; только затем PLL stopped, параметры PLL заменены,
PLL ready, switch PLL и подтверждение. Ни один readiness poll не бесконечный:
100000 iterations максимум на ожидание, watchdog reload каждые256 iterations.
В конце clock-profile crate проверяет registers; nominal 48/24/48 — расчёт,
не измерение генератора, питания, SCK или достаточности timings на этой PCB.
CORE_UPPER_HZ=50000000 — явное экспериментальное допущение для delay,
не подтверждённый предел частоты и не паспортная гарантия.

Watchdog policy после RAM initialization
Никаких enable/unlock/reconfigure. Активный WWDT при включённом peripheral
clock отвергается: слепой reload неизвестного окна может сам вызвать reset.
WDT разрешён reload0xAAAA только при STS[2:0]=0, WIN=0xFFF, DIV<=6 и
(4<<DIV)*(RLD+1)>=4096 LICK ticks. Windowed/updating/tiny profiles отвергаются.
4096 ticks — счётный бюджет, не измеренное время. Reload не спасёт deadline,
истёкший до первого вызова. WDT hardware/option enable state не изменяется.
В integration feeds должны быть в bounded LCD/NOR chunks и sliced delays.

CycleMillis
Nominal DWT CYCCNT→u32 milliseconds, дробная часть сохраняется в u64.
Delta>=2^31 отвергается без изменения состояния. Caller обязан sampling
чаще2^31 core cycles (~44.7s при48MHz); несколько пропущенных оборотов
распознать невозможно. Частоты<1000Hz отвергаются. Output wraps как обычный
u32 deadline counter. Достаточно для UI, не для измерения частоты или RF.

Оставшиеся аппаратные ограничения
Не установлены фактическая PCB/MCU identity, loader handoff, protection,
RF/PA level/effect, питание/LCD interface straps, GPIO mode override,
истинная частота, timing margins и возможность возврата полного стока.
Startup задаёт цифровые requests и ограниченные последовательности; собственно
RF bus shutdown выполняется отдельным diag-quiesce executor. Ни startup,
ни host/emulator success не разрешают TX или не доказывают physical RF-off.
Не прошивать этот этап автоматически. Образ должен быть обозримым кандидатом
для последующей отдельной проверки recovery/loader и физического запуска.
