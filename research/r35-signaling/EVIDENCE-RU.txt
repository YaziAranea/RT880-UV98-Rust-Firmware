2. DTMF / Select V

DTMF использует стандартные пары697/770/852/941 и1209/1336/1477/1633Гц.
BK REG71/72: частота*10.3244, округление до ближайшего слова. REG70 D3D3
для пары и D300 для одиночного тона. Это коэффициенты генераторов звука,
не мощность RF. Сессия сохраняет47/50/70/71/72, временно закрывает местное
аудио, переключает тоны под TX-mute50bit15, возвращает исходные значения.
REG30, PA, PLL, частота и реле внутри сессии не меняются. MIC ADC bit1 REG30
выключает вызывающий runtime только внутри действующего состояния TX.
Восстановление регистров не должно оживлять PA после отмены или ошибки.
Аудит интеграции выявил потерю сохранённых регистров при прямом stop/TOT/fault:
session в foreground могла быть уже сброшена. Runtime теперь сохраняет
baseline50/70 при первом изменении сигналинга; после семи стандартных
независимых off-запросов очищает генераторы70(bits15/7) и TXmute50bit15.
Gain/filter сохраняются. REG30 не оживляется. cleanup_failures bit7 обозначает
ошибку любого из двух запросов; второй выполняется даже при ошибке первого.

DTMF-клавиши работают только при уже начавшейся разрешённой TX. Нажатие
цифры вместе с PTT не должно обходить начальный interlock или менять канал.
Отпускание PTT, EXIT, fault и TOT имеют приоритет над тоном и ANI.

ZVEI1: пять тонов по70мс. CCIR: пять по100мс. ID строго00000..99999.
Повторяющиеся цифры чередуют цифровой тон и repeat:22222 ->2,E,2,E,2.
ZVEI1 E=2600Гц; CCIR E=2110Гц. Паузы между тонами нет.
Select V передаёт числовой ID. Имя возникает из адресной книги принимающей
станции. Произвольный текст имени не кодируется пятью стандартными тонами.
Для текстовой идентичности добавлен APRS callsign и комментарий; это другой
протокол, он не обещает совместимость со штатным proprietary name signaling.

3. GPS

Stock2480C: USART2 base40004400,8N1, только RX. Stock GPS RX PA3/AF7;
PB9HIGH=запрос GPS-on, PB9LOW=off. IRQ38, вектор54. APB1=24МГц.
Драйвер явно выбирает PCLK1 в CRM PICLKS bits3:2=00; независимый старый
источник USART2 не может незаметно испортить рассчитанный baud divider.
Драйвер сохраняет остальные GPIO, не трогает PA2/PA0/PA1/PF1 и UART TX.
При создании питание/NVIC выключены. configure включает только IRQ38;
глобальное разрешение прерываний остаётся root после проверки остальных NVIC.
ISR лишь переносит до8 байтов в512-байтовое SPSC-кольцо. Парсер работает
в foreground с бюджетом до128B за вызов. Ошибка UART/переполнение очищает
парсер и последнее fix. Без свежего корректного RMC/GGA (не старше5s) fix нет.
Байты CRLF/checksum проверяет существующая uv98-gps-nmea.
Подтверждение питания не равно получению спутникового fix.

4. APRS и реальный C-BUS backend

В stock03542 чтение PB4 определяет backend:0=C-BUS;1=отдельный GPIO/TMR3.
В новом драйвере PB4high возвращает UnsupportedBackend, радиопередача
не начинается. Наличие CMX868/868A именно на экземпляре ещё не измерено.

Stock05da0: E1 (30|CFG+F1<<1) 1C => Bell2021200bps, synchronous data buffer.
Stock05de0: E6 bit12=TX data ready; E3=data. Данные по C-BUS MSB-first;
16-bit слово старшим байтом вперёд; в FSK synchronous payload bit0 идёт первым.
Stock21808/2181c обращаются через literal0802197c=40020428 к PB7:
PB7LOW до CMX TX, PB7HIGH после. Это отдельный путь от PC3; PC3 поднимается
в соседней ветке PB4!=0 и не должен меняться для C-BUS без основания.

GPIO: PF1=CSN, PA1=CLOCK, PA0=COMMAND, PA2=REPLY, PB7=audio gate.
Инициализация воспроизводит ожидание100мс, reset01, control1180, затем1140
с конечными ожиданиями50/25/100мс. Начальный disabled E1 не объявляется TX.
E2=303E включает приём Bell202/synchronous. RXready bit6, RXoverflow bit5;
TXunderflow bit11. Ранее bit7 ошибочно рассматривался как overflow при
написании прототипа; исправлен ДО итоговой проверки.

Перед TX нужен строгий callsign, свежий fix, готовый modem и обыкновенный
калиброванный FM-план. Первоначальная готовность модема не является
идентификацией чипа. Нулевой idle-статус допустим после reset и сам по себе
не отвергается. Ограниченный внутренний Bell202/TXbuffer probe при PB7HIGH,
без RF: после10..50мс требуется TXreadybit12, затем E1=0. FFFF отвергается
как возможная плавающая линия. Probe не запрашивает RF TX.
Передача инициируется явно пользователем. Фикс GPS сам маяк не запускает.
Кадр: AX.25 destination APRS, source/SSID, до2 путей,03/F0, uncompressed
position без выдуманных координат, символ, до32 ASCII знаков комментария.
Стандартные FCS/X25, stuffing после5 единиц, NRZI и300ms флаги перед кадром.
Включение подачи аудио происходит после наблюдавшегося TXready и первой
записи в E3. При underflow/timeout путь гасится, частичный кадр отменяется.
После последнего байта выдерживается8ms для окончания сдвигового регистра.
Частота service должна быть выше150Hz (интервал<6.67ms); LCD не может
блокировать feeding. Root обязан дать передаче соответствующий приоритет.

CPS1.10 MainForm.cs stockCFG: callsign3120..3125, SSID3126;
symbol table3127, symbol index3128; comment3129..3256;
path1 3259..3264 /SSID3265, path2 3266..3271 /SSID3272.
Stock stores GBK. Непечатные/не-ASCII комментарии в APRS не транслитерируются
наугад. Некорректный заданный путь отвергается целиком.

5. Граница DSP

BK4819 имеет внутренний DSP/фильтры; MCU пока не получает поток PCM
приёмного звука. Модемные RX данные и REG6F уровня AF — не PCM.
Для программного NR/NB нужна реальная ADC->обработка->DAC цепь или
доказанный внешний ANC-чип. В этой работе не подменяется NR шумодавом,
не включается PC3 наугад и не добавляется декоративная кнопка «DSP».
