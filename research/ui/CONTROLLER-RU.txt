UI controller: каналы, меню, спектр
==================================

Статус
------
Собственная детерминированная UI-политика. Это НЕ восстановленная схема
жестов стоковой UV98 и НЕ аппаратно проверенный интерфейс. Внешний вид может
ориентироваться на привычные любительские станции, но реализация независима.
Контроллер не запускает передачу, не настраивает приёмник, не пишет GPIO,
память или codeplug. Открытый экран спектра не доказывает готовность RF.

Реализация: crates/ui-core, package uv98-ui-core; no_std, forbid(unsafe_code),
без alloc. Зависимости только локальные uv98-keys и uv98-codeplug.
14 синтетических тестов в tests/controller.rs; запуск и результаты сборки
учитываются общим отчётом root, самим автором этого отчёта Cargo не запускался.

Границы модели
--------------
ChannelCatalog предоставляет len() и is_active(index)->Option<bool>.
None означает недоступные метаданные, а не неактивную запись. Каталог содержит
1..=1024 позиций. Его размер проверяется при выборе/перемещении по каналам.
Он не обязан хранить все записи в RAM: firmware adapter может получать одну
48-байтную запись по требованию. Хостовый CodeplugChannels лишь заимствует
готовую секцию 49152 байта, не копирует её и ничего в ней не изменяет.

Проверка active — точная существующая codeplug::channels::Channel::is_active:
record[2] == 1. Это маркер присутствия, не проверка RX/TX режима, частоты,
диапазона, настройки RF или юридических разрешений. include_inactive=true
разрешает выбирать слот без чтения его метаданных; такая UI-навигация не
означает, что этот слот можно настроить в приёмнике.

NavigationPolicy { wrap, include_inactive } задаёт приложение явно.
Если include_inactive=false, начальный и численно выбранный канал должен быть
активным. Up/Down пропускают неактивные записи; недоступная запись даёт ошибку,
не маскируется как inactive. Перебор ограничен count-1 шагами. На границе без
wrap или без другого активного канала выбор остаётся прежним.

View хранит только номер канала, экран, позицию меню, цифровой ввод и PTT.
Записи каналов, график, измерения, частота и пиксели принадлежат адаптерам.
Число bins, положение/границы курсора, диапазон и timing остаются у spectrum
adapter: контроллер их не дублирует и не придумывает stock значения.

События и действия
-----------------
Кнопки уже должны пройти uv98-keys::Debouncer. map action_for_key() превращает
их в стабильные Action. Физические кнопки, PC buttons и скрипт симулятора
должны вызывать один Controller::dispatch(), а не повторять его логику.

Принятая политика, не exact stock mapping:
- Up/Down Pressed: предыдущий/следующий канал; в меню переход; в Spectrum
  MoveSpectrumCursor{Previous/Next}. Автоповтор и long-press не выдумываются.
- Menu Pressed: Confirm. На Channel без ввода открывает меню [Spectrum,Back].
  В Spectrum открывает контекстное меню [ResetPeaks,Back].
- Exit Pressed: отмена всего числового ввода; из меню возврат на исходный
  экран; из Spectrum закрытие спектра и возврат на Channel.
- Digits только на Channel: до четырёх цифр, нумерация 1..1024. Выбор только
  после Menu/Confirm. Ведущие нули сохраняются через NumberEntry.digits.
  Нулевой/вне диапазона/неактивный номер даёт ошибку, ввод остаётся доступен
  для отмены. Up/Down отменяют ввод и выполняют навигацию.
- Star/Hash/Aux16/Aux17/Aux18 не назначены.
- Held/Released обычных клавиш игнорируются. PTT Pressed или Held отмечает
  ptt_pressed=true, закрывает открытый спектр (также из его меню) и запрещает
  повторное открытие. Released снимает запрет, но ничего не возобновляет.
  PTT на Channel не является командой передачи. Физическая защита TX остаётся
  обязанностью отдельного аппаратного слоя, а не выводом из этих тестов.

Menu items — стабильные enum, отображаемые подписи выбирает renderer.
Реестр пунктов и один dispatcher позволяют расширять меню без отдельной
копии логики для hardware кнопок и host UI. Текущих контекстных пунктов два;
перемещение использует длину реестра, а не зашитое переключение 0/1.

Эффекты
-------
Transition { view_changed, effect:Option<Effect> } имеет максимум один эффект:
SelectChannel{index}, OpenSpectrum, CloseSpectrum,
MoveSpectrumCursor{direction}, ResetPeaks.
TX-команды в типе отсутствуют. SelectChannel — UI-намерение, не подтверждение
успешного аппаратного retune. Приложение отдельно обрабатывает ошибки RF.

view_changed=false НЕ означает отсутствие работы: MoveSpectrumCursor меняет
состояние внешнего spectrum adapter; ResetPeaks также требует его обновления.
Renderer должен перерисоваться после применения такого эффекта. OpenSpectrum
повторно не выдаётся, когда спектр уже открыт; вход/выход контекстного меню
не перезапускает sweep. CloseSpectrum повторно не выдаётся после закрытия.

dispatch транзакционен: любая UiError оставляет весь Controller неизменным,
включая незавершённый числовой ввод. PTT/CloseSpectrum/Back не читают каталог;
ошибка или изменение внешнего хранилища не блокируют отмену спектра.

Проверки
--------
Синтетические сценарии покрывают:
- пустой/слишком большой каталог, неверный initial index, inactive/unavailable;
- границы и wrap, skip inactive, bounded search, единственный канал;
- числовой ввод 1 и 1024, leading zeros, invalid digit, 5-я цифра, atomic errors;
- вход/выход обоих меню, stable item IDs, сохранение исходного канала;
- отдельные cursor effects, отсутствие неявного выбора канала в Spectrum;
- peak reset, отсутствие повторного Open/Close при контекстных переходах;
- PTT из context menu, запрет reopen, release без auto restart;
- изменение размера каталога и независимая от него отмена;
- отсутствие repeat/aux gestures и сохранение всех полей при ignored input;
- exact-length host adapter, record[2] == 1, unchanged original bytes.

Источники границ
---------------
research/keys/EVIDENCE-RU.txt: происхождение Key и входных декодеров,
ограничения физической разводки и stock timing.
crates/keys/src/lib.rs, src/debounce.rs: Key/ButtonEvent, внешнее debounce.
crates/codeplug/src/channels.rs: CHANNEL_COUNT=1024, CHANNEL_LEN=48,
is_active byte2, borrowed access без нормализации/записи.
research/cps: доказательства layout CPS. Новая UI-политика выше является
проектным решением; бинарник stock не использован для её объявления точной.
