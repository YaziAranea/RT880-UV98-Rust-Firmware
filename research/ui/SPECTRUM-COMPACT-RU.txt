UV-98 Plus: компактный обзор диапазона, 2026-11-09

Статус: исходники чистого протокола и экрана. Host-тесты/PNG запускает общий
сборочный этап. До отдельного live-подтверждения это не доказательство работы RF.

Источник идей: первичное руководство Karina, раздел 4, получено GitHub plugin:
https://github.com/autumn1rain/karina-v3-k1/blob/main/site-docs/ru/manual.md
GitHub blob SHA cc43616574a6ed67f1996c3878c5af9810102f6f.
Использованы идеи явных границ/шага, курсора и просмотра пиков. Код, изображения,
шрифты, таблицы, распиновка и регистры Karina не перенесены. Наша реализация
самостоятельная; лицензия чужого исходного кода не переносится через копирование.

Модель crates/spectrum/src/compact.rs:
- не более81 точки, integer10Hz; два массива u16 плюс valid/fresh/peak_valid;
- compile-time Plot<=368B, Engine<1024B, без heap, unsafe, RF, COM;
- каждое действие имеет монотонный u64 ticket, старые/нефазовые ACK игнорируются;
- Prepare ACK → Tune ACK → минимум settle_ms → Read ACK; время не создаёт ACK;
- settle начинается после Tuned (пачка регистров действительно завершена);
- Exit/PTT/Accept всегда требуют Restore полного обычного RX, не только частоты;
- до Restore ACK нельзя начинать следующий обзор; ошибку/timeout восстановления
  адаптер переводит в свой terminal-safe-off, не изображает работающий приёмник;
- PTT отменяет обзор, release сам не запускает обзор/передачу;
- один ticket резервируется для Restore, переполнение счётчика не повторяет ticket;
- шкала raw0..511, значение>511 — ошибка источника, а не молчаливый clamp;
- valid отличает неизвестное от измеренного нуля, fresh отличает прошлый проход;
- ClearPeaks убирает только историю пиков, не измерения.

Обязанности аппаратного адаптера:
- до Prepare проверить все81 частоты, реальный RF route, calibration band,
  RX chain и фиксированный gain; ограничить окно внутри одной доказанной области;
- TX должен быть выключен, звук приглушён; не менять заводскую NOR/калибровки;
- минимальная задержка для исследованного штатного пути не менее10ms;
- исполнять stock-подтверждённую ограниченную пачку быстро, а ожидание неблокирующе;
- после Stop/Accept восстановить полный обычный RX/звук и только затем ACK;
- raw PTT отменяет независимо от GUI, TX требует отпустить и нажать заново;
- snapshot для LCD копировать только после завершения предыдущей отрисовки,
  публиковать2–5Hz: потоковый renderer не должен видеть разную сетку между строками.

Экран240x320, однострочный буфер480B:
- большая частота курсора56..77; границы84..91; шкала/легенда96..103;
- график110..223, свежие данные cyan, старые grey, пики yellow;
- курсор под графиком225..232: движение не перерисовывает сам график;
- raw выбранной точки240..247 с пометкой прохода; длина/шаг254..261;
- статус269..276, пояснение PTT283..290, MENU принять/EXIT возврат в footer;
- неизвестный snapshot: «НЕТ ИЗМЕРЕНИЙ», без выдуманного шума или S/dBm.

Меню: FM/AM непосредственно в корне; остальные настройки в5 разделах.
Все списки максимум7 видимых строк; перемещение курсора перерисовывает только
две строки и позицию, не прокручивает весь список при каждом нажатии.

Долгое0 по умолчанию запрашивает спектр. Короткое0 остаётся цифрой при вводе.
Все10 цифр переназначаются; прежние значения долгих1–9 сохранены. Внутренний
binding_index9 отображается как физическая цифра0, не как несуществующая «10».
В шапке и «О прошивке» видна ревизия0.1.8-r4; имя бинарного протокола0.1.8 прежнее.

Дополнение отмены: пока Restore(Accepted) не подтверждён, PTT/EXIT заменяет
его новым Restore исходной частоты. Старый ticket больше не может подтвердить
выбор. Повторные Stop/heldPTT уже начатого обычного Restore не продлевают timeout.
